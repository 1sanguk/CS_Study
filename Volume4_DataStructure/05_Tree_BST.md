# 05. Tree와 BST

> 게임 서버·백엔드 개발자를 위한 CS 면접 교재

## 학습 목표

- 트리의 기본 용어와 대표 순회 방식을 설명할 수 있다.
- 이진 탐색 트리의 탐색·삽입·삭제 과정을 설명할 수 있다.
- BST의 성능이 높이에 좌우되는 이유와 균형 트리가 필요한 이유를 설명할 수 있다.
- 계층 표현과 정렬 검색이라는 서로 다른 요구에 맞춰 트리를 선택할 수 있다.

## 1. 개요

트리(Tree)는 노드 사이의 부모·자식 관계로 계층을 표현하는 자료구조다. 파일 시스템, 조직도, 게임의 씬 그래프처럼 한 요소 아래에 여러 요소가 이어지는 관계에 적합하다.

이진 트리(Binary Tree)는 각 노드의 자식이 최대 두 개인 트리다. 이진 탐색 트리(Binary Search Tree, BST)는 여기에 다음 순서 규칙을 추가한다.

- 한 노드의 왼쪽 서브트리에 있는 모든 Key는 그 노드의 Key보다 작다.
- 오른쪽 서브트리에 있는 모든 Key는 그 노드의 Key보다 크다.
- 각 서브트리도 같은 규칙을 만족한다.

중복 Key를 허용한다면 `같은 Key는 항상 오른쪽에 둔다`, `노드에 개수를 저장한다` 같은 정책을 별도로 정해야 한다. 단순히 “왼쪽은 작고 오른쪽은 크다”만으로는 중복을 처리할 수 없다.

BST는 정렬된 배열처럼 Key의 순서를 이용해 탐색 범위를 줄이면서도, 연결 구조를 이용해 삽입과 삭제를 수행한다. 다만 성능은 노드 수가 아니라 트리의 높이에 직접 영향을 받는다.

## 2. 트리의 기본 용어

다음 트리를 기준으로 용어를 정리해 보자.

```text
             A                 depth 0
          /     \
         B       C             depth 1
       /  \       \
      D    E       F           depth 2
          /
         G                      depth 3
```

- **Root**: 부모가 없는 최상위 노드다. 위에서는 `A`다.
- **Parent / Child**: 직접 연결된 상위·하위 노드다. `B`는 `D`, `E`의 부모다.
- **Sibling**: 같은 부모를 둔 노드다. `B`와 `C`가 형제다.
- **Leaf**: 자식이 없는 노드다. `D`, `F`, `G`다.
- **Subtree**: 어떤 노드와 그 아래 후손으로 이뤄진 작은 트리다.
- **Depth**: 루트에서 해당 노드까지의 간선 수다. `G`의 깊이는 3이다.
- **Height**: 해당 노드에서 가장 먼 Leaf까지의 간선 수다. 트리 높이는 루트 높이와 같다.

깊이는 루트에서 아래로 측정하고, 높이는 노드에서 가장 깊은 Leaf까지 측정한다. 면접에서는 노드 수로 세는 정의도 있으므로 먼저 “간선 수 기준으로 설명하겠습니다”라고 기준을 밝히면 혼동을 줄일 수 있다.

모든 이진 트리가 BST인 것은 아니다. 이진 트리는 자식 수만 제한하고, BST는 추가로 Key의 순서까지 제한한다. 완전 이진 트리는 마지막 레벨을 제외한 레벨이 모두 차 있고 마지막 레벨이 왼쪽부터 채워진 형태다. Heap은 이 완전 이진 트리 형태를 이용하지만, BST와는 다른 순서 규칙을 가진다.

## 3. 트리 순회

순회(Traversal)는 모든 노드를 정해진 순서로 한 번씩 방문하는 작업이다. 같은 트리라도 방문 시점에 따라 결과와 용도가 달라진다.

```text
        8
      /   \
     3     10
    / \      \
   1   6      14
```

| 순회 | 방문 순서 | 위 트리의 결과 | 대표 용도 |
|---|---|---|---|
| 전위(Preorder) | Root → Left → Right | 8, 3, 1, 6, 10, 14 | 트리 복사, 계층 직렬화 |
| 중위(Inorder) | Left → Root → Right | 1, 3, 6, 8, 10, 14 | BST Key의 오름차순 처리 |
| 후위(Postorder) | Left → Right → Root | 1, 6, 3, 14, 10, 8 | 자식 정리 후 부모 삭제 |
| 레벨 순서 | 위 레벨부터 왼쪽→오른쪽 | 8, 3, 10, 1, 6, 14 | 거리·단계별 처리, BFS |

전위·중위·후위 순회는 재귀 호출이나 명시적인 Stack으로 구현할 수 있다. 레벨 순회는 Queue를 사용한다. 재귀 구현은 간결하지만 높이가 매우 큰 트리에서는 호출 Stack이 깊어질 수 있다. 외부 입력으로 만들어져 편향될 수 있는 트리라면 반복문과 명시적 Stack 사용도 검토해야 한다.

일반적인 순회는 노드 `n`개를 모두 방문하므로 `O(n)`이다. BST라고 해서 전체 순회가 `O(log n)`이 되는 것은 아니다. `O(log n)`은 균형 잡힌 경우 하나의 Key를 찾는 경로에 대한 비용이다.

## 4. BST의 핵심 동작 원리

### 탐색

찾으려는 Key를 현재 노드와 비교한다. 같으면 성공하고, 작으면 왼쪽, 크면 오른쪽으로 이동한다.

```text
Key 6 탐색

8과 비교: 6 < 8  → 왼쪽
3과 비교: 6 > 3  → 오른쪽
6과 비교: 같음   → 탐색 성공
```

한 단계마다 한 서브트리를 버릴 수 있으므로 비용은 지나간 경로 길이, 즉 높이 `h`에 비례해 `O(h)`다.

### 삽입

탐색과 같은 비교를 반복하다가 비어 있는 자식 위치에 새 노드를 연결한다. Key `7`을 삽입하면 `8 → 3 → 6`을 거쳐 `6`의 오른쪽 자식이 된다. 연결 자체는 `O(1)`이지만 위치를 찾는 데 `O(h)`가 걸린다.

중복 Key 정책은 삽입 전에 결정해야 한다. 사용자 ID처럼 유일해야 하는 Key라면 기존 노드를 찾았을 때 삽입을 거부한다. 점수처럼 같은 값이 가능하다면 `(score, playerId)` 복합 Key로 유일한 순서를 만들거나, 한 Key 아래에 여러 값을 저장할 수 있다.

### 삭제

삭제는 대상 노드의 자식 수에 따라 세 경우로 나뉜다.

1. **자식이 없다**: 부모가 가리키는 연결을 제거한다.
2. **자식이 하나다**: 부모가 삭제 노드 대신 그 자식을 가리키게 한다.
3. **자식이 둘이다**: 중위 후속자(Inorder Successor) 또는 중위 선행자로 대체한 뒤, 옮겨 온 원래 노드를 삭제한다.

중위 후속자는 오른쪽 서브트리에서 가장 작은 노드다. 이 노드는 왼쪽 자식이 없으므로 최종 삭제가 자식 0개 또는 1개인 단순한 경우로 바뀐다.

```text
삭제 전: 8의 자식이 둘

        8
      /   \
     3     10
          /  \
         9    14

오른쪽 서브트리의 최소값 9로 8을 대체

        9
      /   \
     3     10
               \
                14
```

삭제 역시 대상과 대체 노드를 찾는 경로 때문에 `O(h)`다. 실제 라이브러리의 균형 트리는 삭제 뒤 회전과 색상 조정 같은 재균형 작업도 수행한다.

## 5. 높이와 시간 복잡도

노드가 양쪽에 고르게 분산되면 높이는 대략 `log₂ n`이다. 반대로 정렬된 Key를 단순 BST에 차례로 삽입하면 한쪽 자식만 이어지는 연결 리스트 형태가 될 수 있다.

```text
균형에 가까운 형태          1, 2, 3, 4 순서 삽입 후 편향

        4                   1
      /   \                  \
     2     6                  2
    / \   / \                  \
   1  3  5  7                  3
                                  \
                                   4

높이 O(log n)              높이 O(n)
```

| 연산 | 균형에 가까운 BST | 편향된 BST |
|---|---:|---:|
| 탐색 | O(log n) | O(n) |
| 삽입 | O(log n) | O(n) |
| 삭제 | O(log n) | O(n) |
| 최소·최대 | O(log n) | O(n) |
| 전체 순회 | O(n) | O(n) |

따라서 “BST 탐색은 O(log n)”이라는 답은 조건이 빠져 있다. 정확한 표현은 “BST 연산은 `O(h)`이며, 균형이 유지되어 `h = O(log n)`일 때 `O(log n)`이다”이다. AVL Tree와 Red-Black Tree는 재균형을 통해 최악 높이를 `O(log n)`으로 제한한다.

## 6. 순서가 있어서 가능한 연산

Hash Table은 평균적으로 정확한 Key 조회가 빠르지만 Key 사이의 대소 관계를 보존하지 않는다. BST는 순서 규칙 덕분에 다음 연산을 자연스럽게 지원한다.

- 최소값과 최대값 찾기
- 어떤 Key 이상의 첫 원소인 `lower_bound` 찾기
- 어떤 Key보다 큰 첫 원소인 `upper_bound` 찾기
- `[L, R]` 범위의 Key를 정렬 순서로 순회하기
- 현재 Key의 바로 이전·다음 원소 찾기

범위 조회는 시작 지점을 `O(log n)`에 찾고 결과 `k`개를 순회하므로 균형 트리에서 보통 `O(log n + k)`로 표현한다. 랭킹에서 특정 점수 구간의 플레이어를 조회하거나, 예약 실행 시각 이후의 첫 작업을 찾는 요구에 유용하다.

다만 “k번째로 작은 값”을 `O(log n)`에 찾으려면 각 노드에 서브트리 크기 같은 추가 정보를 유지해야 한다. 기본 BST만으로는 중위 순회를 진행하며 세어야 하므로 최악 `O(n)`이다.

## 7. 비슷한 개념과 비교

| 구조 | 정렬 유지 | 대표 조회 | 삽입·삭제 | 적합한 요구 |
|---|---|---|---|---|
| 정렬 배열 | O | 이진 탐색 O(log n) | 중간 이동 O(n) | 조회가 많고 갱신이 적음 |
| 단순 BST | O | 평균 O(log n), 최악 O(n) | 평균 O(log n), 최악 O(n) | 학습용, 입력 편향을 통제 가능 |
| 균형 BST | O | 최악 O(log n) | 최악 O(log n) | 범위·순서 조회와 지속적 갱신 |
| Hash Table | X | 평균 O(1) | 평균 O(1) | 정확한 Key 조회 중심 |
| Heap | 최솟값/최댓값만 보장 | Top O(1) | 삽입·제거 O(log n) | 우선순위가 가장 높은 원소 처리 |

정렬된 배열은 메모리가 연속되어 Cache 지역성이 좋다. 원소 수가 작거나 변경이 드물면 포인터를 따라가는 트리보다 실제로 빠를 수 있다. 반면 연결 노드 기반 트리는 노드별 할당과 포인터 저장 비용이 있고 메모리 접근이 흩어질 수 있다.

언어의 `map`, `set`, `SortedDictionary` 같은 정렬 컨테이너는 일반적으로 단순 BST가 아니라 균형 트리를 사용한다. 구현 세부사항은 언어와 버전에 따라 확인해야 하며, 컨테이너 이름만 보고 특정 트리라고 단정하지 않는다.

## 8. 장점과 단점

### 장점

- 일반 Tree는 계층과 포함 관계를 자연스럽게 표현한다.
- BST는 탐색·삽입·삭제와 정렬 순회를 한 구조에서 제공한다.
- 균형 BST는 최악의 주요 연산을 `O(log n)`으로 제한한다.
- 범위 조회, 선행자·후속자 검색처럼 순서 기반 연산에 유리하다.

### 단점

- 단순 BST는 입력 순서에 따라 `O(n)`으로 편향될 수 있다.
- 노드, 자식 포인터, 균형 정보 때문에 배열보다 메모리 오버헤드가 크다.
- 포인터 추적과 개별 할당은 Cache 효율을 떨어뜨릴 수 있다.
- 회전과 연결 변경이 있으므로 동시 수정과 참조 수명 관리가 복잡하다.

## 9. 게임 서버·백엔드 실무 예시

### 게임 씬과 스킬 계층

게임의 씬 노드는 부모 Transform을 기준으로 자식 Transform을 계산할 수 있다. 부모를 이동하면 후손의 월드 좌표도 영향을 받는다. 이때는 Key의 대소보다 부모·자식 관계가 핵심이므로 일반 Tree가 적합하다. 스킬 선행 조건이나 길드 조직도도 비슷하다.

노드를 제거할 때 후위 순회를 사용하면 자식 리소스를 먼저 정리하고 부모를 마지막에 정리할 수 있다. 반면 UI나 설정을 부모부터 적용해야 한다면 전위 순회가 자연스럽다.

### 예약 작업과 범위 조회

서버가 `(실행 시각, 작업 ID)`를 Key로 균형 트리에 예약 작업을 저장한다고 하자. 현재 시각 이하의 첫 구간을 순서대로 꺼낼 수 있고, 특정 시간 범위의 작업도 조회할 수 있다. 정확한 ID 취소가 매우 빈번하다면 ID용 Hash Map과 시간 순서용 Tree를 함께 유지할 수도 있다.

두 인덱스를 함께 유지하면 조회는 편해지지만 삽입·삭제 시 둘 다 원자적으로 갱신해야 한다. 하나만 갱신되면 유령 작업이나 누락이 생긴다. 자료구조 선택은 Big-O뿐 아니라 불변식 유지 비용까지 포함한다.

### 랭킹

점수순 랭킹에는 `(score, playerId)`처럼 동점까지 구분하는 Key가 필요하다. 균형 BST는 점수 범위 순회에 유리하지만 순위, 즉 k번째 원소를 빠르게 구하려면 서브트리 크기를 유지하는 Order Statistic Tree 같은 확장이 필요하다. 대규모 서비스에서는 Redis Sorted Set이나 DB Index처럼 검증된 외부 구조를 선택할 수 있다.

공유 트리는 자동으로 Thread-safe하지 않다. 여러 Thread가 동시에 삽입·삭제하면 연결과 균형 정보가 깨질 수 있다. 단일 소유 Thread, Lock, Snapshot 등 접근 정책을 별도로 설계해야 한다.

## 10. 자주 하는 오해

- **이진 트리와 BST는 같다**: 이진 트리는 자식 수 조건이고, BST는 Key 순서 조건까지 가진다.
- **BST 탐색은 항상 O(log n)이다**: 높이가 `O(log n)`으로 유지될 때만 그렇다. 단순 BST는 최악 `O(n)`이다.
- **중위 순회는 모든 이진 트리를 정렬한다**: BST의 순서 불변식이 있을 때만 오름차순 결과가 나온다.
- **Root가 바뀌면 데이터 주소도 모두 바뀐다**: 구현에 따라 다르다. 연결 구조의 회전은 링크를 바꾸지만 객체 이동 여부는 컨테이너 구현에 달려 있다.
- **Tree는 Hash Table보다 항상 느리다**: 정확한 Key 한 건 조회는 Hash가 유리한 경우가 많지만, 정렬·범위·최악 시간 요구에서는 균형 Tree가 적합할 수 있다.
- **한 자료구조로 모든 조회를 해결해야 한다**: ID 조회와 시간순 처리가 모두 중요하면 Hash와 Tree 등 여러 인덱스를 함께 쓸 수 있다.

## 11. 면접 질문

### Q1. Tree와 BST의 차이를 설명해 주세요.

Tree는 부모·자식 관계로 계층을 표현하는 일반 구조입니다. 이진 트리는 자식 수가 최대 두 개이고, BST는 왼쪽 Key가 작고 오른쪽 Key가 크다는 순서 불변식을 추가한 이진 트리입니다. 따라서 BST를 중위 순회하면 Key가 정렬된 순서로 나옵니다.

### Q2. BST의 탐색·삽입·삭제 복잡도는 얼마인가요?

모두 트리 높이 `h`에 비례해 `O(h)`입니다. 균형이 잡혀 높이가 `O(log n)`이면 각 연산도 `O(log n)`이지만, 한쪽으로 편향되면 높이가 `n`이 되어 최악 `O(n)`입니다.

### Q3. 자식이 둘인 노드는 어떻게 삭제하나요?

오른쪽 서브트리의 최소 노드인 중위 후속자나 왼쪽 서브트리의 최대 노드인 중위 선행자로 대상 노드를 대체합니다. 그 후 원래 위치의 대체 노드를 삭제하면 자식이 0개 또는 1개인 문제로 단순화됩니다.

### Q4. 전위·중위·후위 순회는 언제 사용하나요?

전위는 부모를 먼저 직렬화하거나 설정을 전파할 때, 중위는 BST를 정렬 순서로 처리할 때, 후위는 자식을 먼저 정리하고 부모를 삭제할 때 유용합니다. 레벨 순회는 Queue를 이용해 가까운 레벨부터 처리합니다.

### Q5. BST와 Hash Table 중 무엇을 선택하겠습니까?

정확한 Key 조회만 중요하면 평균 `O(1)`인 Hash Table을 우선 검토합니다. Key의 정렬 순회, 범위 조회, 선행자·후속자 또는 안정적인 최악 성능이 필요하면 균형 BST가 적합합니다. 실제 선택에서는 원소 수와 메모리, 동시성 요구도 함께 봅니다.

### Q6. 정렬된 배열과 균형 BST를 비교해 주세요.

둘 다 조회는 `O(log n)`이 가능하지만, 정렬 배열은 연속 메모리라 순회와 Cache 효율이 좋고 중간 삽입·삭제가 `O(n)`입니다. 균형 BST는 삽입·삭제가 `O(log n)`이지만 포인터와 할당 오버헤드가 있습니다.

## 13. 30초 모범답변

> Tree는 부모·자식 관계로 계층을 표현하고, BST는 왼쪽 Key가 작고 오른쪽 Key가 크다는 규칙을 추가한 이진 트리입니다. BST의 탐색·삽입·삭제는 높이 `h`에 비례해 `O(h)`이며, 균형이 잡히면 `O(log n)`이지만 편향되면 `O(n)`입니다. 정렬 순회와 범위 검색이 필요할 때 유용하고, 실무에서는 보통 균형 BST를 사용합니다.

## 14. 1~2분 확장답변

> Tree는 Root에서 시작하는 부모·자식 구조이며 파일 시스템, 게임 씬, 스킬 선행 관계 같은 계층을 표현합니다. 이진 트리는 자식이 최대 두 개이고, BST는 각 노드 기준으로 왼쪽 서브트리 Key가 작고 오른쪽이 크다는 불변식을 가집니다. 그래서 비교 결과에 따라 한쪽 서브트리만 따라가며 탐색하고, 중위 순회하면 정렬된 결과를 얻습니다.
>
> 탐색·삽입·삭제 비용은 모두 높이 `h`에 비례합니다. 균형 상태에서는 높이가 `O(log n)`이지만 정렬된 입력이 단순 BST에 들어오면 연결 리스트처럼 편향되어 최악 `O(n)`이 됩니다. 그래서 표준 정렬 Map이나 Set은 AVL이나 Red-Black Tree 같은 균형 트리를 사용합니다. Hash Table은 정확한 Key 조회가 평균적으로 더 빠르지만 순서를 보존하지 않으므로, 범위 조회나 다음 Key 검색이 필요하면 균형 BST가 유리합니다. 게임 서버에서는 시간순 예약 작업이나 점수 구간 랭킹에 활용할 수 있고, 동시 접근과 중복 Key 정책은 별도로 설계해야 합니다.

## 15. 핵심 요약

- Tree는 부모·자식의 계층 구조이고, 이진 트리는 자식이 최대 두 개인 Tree다.
- BST는 `왼쪽 Key < 현재 Key < 오른쪽 Key` 순서 불변식을 재귀적으로 유지한다.
- 중위 순회는 BST의 Key를 오름차순으로 방문한다.
- 탐색·삽입·삭제는 `O(h)`이며 균형 상태에서는 `O(log n)`, 편향되면 `O(n)`이다.
- 자식이 둘인 노드는 중위 후속자나 선행자로 대체해 삭제한다.
- BST는 정렬, 범위, 선행자·후속자 조회에 유리하고 Hash Table은 정확한 Key 조회에 유리하다.
- 실무에서는 균형, 중복 Key, 메모리, 동시 접근 정책까지 함께 고려한다.

## 한 줄 정리

> BST는 Key의 순서로 탐색 범위를 줄이는 Tree이며, 성능을 `O(log n)`으로 유지하려면 높이의 균형이 핵심이다.
