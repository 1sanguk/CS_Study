# 04. 동시성과 병렬성

> 게임 서버·백엔드 개발자를 위한 CS 면접 교재

## 학습 목표

- 핵심 정의와 등장 이유를 설명할 수 있다.
- 대표 동작 과정과 유사 개념의 차이를 설명할 수 있다.
- 게임 서버 장애와 설계에 적용할 수 있다.

## 1. 개요

동시성(Concurrency)은 여러 작업이 겹친 시간에 진행되는 구조이고, 병렬성(Parallelism)은 여러 작업이 실제로 동시에 실행되는 상태이다.

동시성은 작업을 분리하고 진행 상태를 관리하는 소프트웨어 구조에 가깝다. 단일 코어가 A와 B를 짧게 번갈아 실행해도 두 작업은 같은 시간 구간에 진행된다. 병렬성은 하드웨어 실행 관점이다. 둘 이상의 코어가 A와 B를 같은 순간에 실행해야 한다. 병렬 프로그램은 여러 작업을 동시에 다루므로 동시성 문제도 함께 가지지만, 동시 프로그램이 반드시 병렬로 실행되는 것은 아니다.

## 2. 왜 필요한가

I/O 대기 중 다른 일을 진행해 자원을 활용하고, 다중 코어로 계산 처리량을 높이기 위해 필요하다.

운영체제는 제한된 CPU와 메모리를 여러 작업에 안전하고 효율적으로 나누어야 한다. 개발자는 추상화가 감추는 비용과 공유 범위를 알아야 성능 저하와 동시성 버그를 진단할 수 있다.

## 3. 핵심 동작 원리

```text
단일 코어 동시성: 작업 A와 B를 번갈아 실행 / 다중 코어 병렬성: 코어마다 A와 B를 동시에 실행
```

운영체제는 사용자 프로그램이 직접 하드웨어와 다른 프로세스의 자원을 침범하지 않도록 권한과 상태를 관리한다. 실행 단위가 대기하면 다른 준비 작업을 실행하고, 다시 실행할 때 필요한 문맥을 복원한다.

비동기는 완료를 기다리는 동안 호출 흐름을 막지 않는 프로그래밍 방식이고 동시성과 관련되지만 동일하지 않다. 멀티스레딩도 단일 코어에서는 병렬이 아닐 수 있다.

### 세 개념의 실행 모습

```text
동시성, 단일 코어
시간 ─────────────────────────>
Core 0: [ A ][ B ][ A ][ B ][ A ]

병렬성, 다중 코어
시간 ─────────────────────────>
Core 0: [       A       ][  A  ]
Core 1: [       B       ][  B  ]

비동기 I/O
Task A: [요청] ............ [완료 처리]
Thread: [Task B][Task C]... [Task A 계속]
```

비동기 예시의 점 구간에서는 외부 장치나 DB가 작업을 수행하고 호출 스레드는 다른 일을 할 수 있다. 비동기 API를 호출했다고 CPU 계산이 자동으로 다른 코어에서 병렬 실행되는 것은 아니다. 반대로 스레드 풀에 CPU 계산을 맡기면 호출자는 비동기적으로 기다릴 수 있고 작업은 다른 코어에서 병렬 실행될 수도 있다.

### 작업 분해와 합류

병렬화하려면 큰 작업을 서로 독립적인 작은 작업으로 나누고 결과를 합쳐야 한다. 분할 자체, 작업 큐 등록, 동기화, 결과 병합에도 비용이 든다. 매우 작은 계산을 수천 개 작업으로 나누면 실제 계산보다 스케줄링 비용이 커질 수 있다.

```text
입력 World Snapshot
   ├─ Region A 계산 ─┐
   ├─ Region B 계산 ─┼─ Barrier ─> 결과 반영
   └─ Region C 계산 ─┘
```

Barrier는 모든 병렬 작업이 끝날 때까지 다음 단계가 기다리는 지점이다. 가장 느린 작업이 전체 완료 시간을 결정할 수 있으므로 작업량을 균등하게 나누는 것이 중요하다. 한 지역에 플레이어가 몰리면 정적 분할의 부하가 불균형해질 수 있다.

### 병렬화 한계

전체 작업 중 순차적으로 실행해야 하는 부분은 코어를 늘려도 줄지 않는다. 예를 들어 한 틱의 40%가 반드시 단일 스레드에서 상태를 반영해야 한다면 나머지 60%를 빠르게 만들어도 전체 속도 향상에는 한계가 있다. 이를 정량화하는 Amdahl의 법칙을 면접에서 증명할 필요는 없지만, 순차 구간과 동기화가 병렬 확장의 상한을 만든다는 원리는 설명할 수 있어야 한다.

공유 데이터에 락을 많이 걸면 코어들은 계산보다 락을 기다린다. 같은 캐시 라인의 서로 다른 값을 여러 코어가 자주 쓰는 False Sharing도 캐시 일관성 트래픽을 만들 수 있다. 병렬화를 위해서는 단순히 스레드를 추가하기보다 데이터 소유권과 작업 경계를 함께 바꿔야 한다.

## 4. 쉬운 예시

게임 서버가 네트워크 입력을 기다리는 동안 랭킹 요청을 처리하면 여러 작업이 진전된다. CPU 계산을 여러 코어에 분배하면 실제 동시 실행도 가능하다. 다만 같은 플레이어 상태를 함께 변경한다면 순서와 동기화를 정의해야 한다.

식당 주문에 비유하면 한 직원이 주문 접수 후 조리를 기다리는 동안 다음 주문을 받는 것은 동시성에 가깝다. 여러 요리사가 실제로 서로 다른 음식을 같은 순간에 만드는 것은 병렬성이다. 기술적으로는 네트워크 응답 대기 중 이벤트 루프가 다른 소켓을 처리하는 것이 전자이고, 경로 탐색 작업을 여러 코어에서 계산하는 것이 후자다.

## 6. 장점과 단점

운영체제 추상화는 격리, 자원 공유, 응답성과 처리량을 제공한다. 반면 관리 구조, 스케줄링, 문맥 교환, 동기화에는 비용이 있다. 작업 수를 늘리는 것만으로 성능이 비례해 증가하지 않는다.

동시성의 장점은 느린 I/O가 다른 요청 진행을 막지 않아 응답성과 자원 활용이 좋아지는 것이다. 단점은 실행 순서가 다양해지고 취소와 오류 전달, 공유 상태의 정합성이 복잡해진다는 점이다. 병렬성은 CPU 계산 처리량을 높이지만 분할 가능한 작업에만 효과가 있고 동기화와 캐시 비용을 만든다.

## 7. 게임 서버·백엔드 실무 예시

게임 서버는 소켓 I/O는 비동기로 겹쳐 처리하고, 독립적인 룸이나 경로 탐색은 여러 코어에 병렬 배치할 수 있다. 공유 월드 상태를 병렬화하면 락과 결정성 비용을 함께 고려한다.

관찰할 때는 평균 CPU만 보지 않고 스레드 수, 실행 큐, 문맥 교환, 메모리, 락 대기와 꼬리 지연을 같은 시간축에서 확인한다.

룸 단위로 한 스레드만 상태를 변경하게 하면 룸 내부의 실행 순서를 단순하게 유지하면서 여러 룸을 코어에 나눠 병렬 실행할 수 있다. 플레이어가 룸을 이동할 때는 두 소유자 사이의 메시지 순서와 인계 시점을 정의한다. 하나의 거대한 월드를 병렬화한다면 읽기용 스냅샷, 단계별 Barrier, 명령 버퍼 등으로 읽기와 쓰기 시점을 분리할 수 있다.

재현 가능한 전투 결과가 중요하면 병렬 작업 완료 순서가 결과에 영향을 주지 않게 해야 한다. 부동소수점 누적 순서, 동일 우선순위 이벤트의 처리 순서, 난수 스트림을 고정한다. 성능 향상을 얻었더라도 결과가 실행마다 달라지면 리플레이와 버그 분석이 어려워진다.

## 8. 자주 하는 오해

- 실행 단위와 자원 소유 단위를 같은 개념으로 본다.
- 스레드를 늘리면 처리량이 항상 증가한다고 생각한다.
- 비동기와 병렬 실행을 같은 의미로 사용한다.
- CPU 사용률이 낮으면 서버에 병목이 없다고 단정한다.
- 운영체제 추상화의 비용은 무시해도 된다고 생각한다.

### 최종 실무 판단 기준

- **요구 확인**: 동시성(Concurrency)은 여러 작업이 겹친 시간에 진행되는 구조이고, 병렬성(Parallelism)은 여러 작업이 실제로 동시에 실행되는 상태이다. 이 내용을 적용하기 전에 데이터 규모, 호출 빈도와 허용 지연을 수치로 확인한다. 같은 기술도 요청량과 정확성 요구가 달라지면 적합한 선택이 달라질 수 있다.
- **정확성 경계**: 필요한 이유는 제한된 자원의 보호와 효율적 사용이다. 정상 흐름만 설명하지 않고 중복, 역순, 동시 실행과 부분 실패에서 어떤 불변식을 지켜야 하는지 함께 명시한다.
- **비용 비교**: 공유 범위와 실행 단위를 구분해야 한다. 평균 복잡도나 처리량 하나만 보지 않고 Memory, CPU, I/O, Lock 대기와 구현 복잡도까지 비교한다.
- **장애 대응**: 동시성과 병렬성 관련 구성 요소가 느려지거나 중단됐을 때 Timeout, Retry 상한, Backpressure와 복구 순서를 정한다. Retry가 중복 부작용이나 연쇄 부하를 만들지 검증한다.
- **운영 검증**: 동시성과 병렬성에서는 기능 Test와 함께 경계값, Peak 부하와 장애 주입 Test를 수행한다. 처리 시간 p95·p99, 오류율, Queue와 Resource 사용량을 관찰하고 변경 전후 결과를 비교한다.

동시성과 병렬성 답변에서는 이 기준으로 답하면 개념 정의에 그치지 않고 선택 조건, Trade-off와 실무 검증 방법까지 논리적으로 연결할 수 있다.

## 9. 면접 질문

### Q1. 핵심 개념을 한 문장으로 설명해 주세요.

동시성(Concurrency)은 여러 작업이 겹친 시간에 진행되는 구조이고, 병렬성(Parallelism)은 여러 작업이 실제로 동시에 실행되는 상태이다.

### Q2. 왜 필요한가요?

I/O 대기 중 다른 일을 진행해 자원을 활용하고, 다중 코어로 계산 처리량을 높이기 위해 필요하다.

### Q3. 게임 서버에서는 어떻게 적용하나요?

게임 서버는 소켓 I/O는 비동기로 겹쳐 처리하고, 독립적인 룸이나 경로 탐색은 여러 코어에 병렬 배치할 수 있다. 공유 월드 상태를 병렬화하면 락과 결정성 비용을 함께 고려한다.

### Q4. 성능 문제는 무엇을 확인하나요?

CPU 사용률과 함께 실행 큐, 전환 횟수, 대기 원인, 메모리와 p95·p99 지연을 확인한다.

### Q5. 비동기와 병렬성은 어떻게 다른가요?

비동기는 작업 완료를 기다리는 동안 호출 흐름을 막지 않는 방식이고 단일 스레드에서도 가능하다. 병렬성은 여러 작업이 여러 실행 자원에서 같은 순간 실제로 수행되는 것이다. 비동기 I/O가 CPU 계산을 자동으로 병렬화하지는 않는다.

### Q6. 코어를 늘려도 성능이 비례하지 않는 이유는 무엇인가요?

순차 실행 구간은 그대로 남고 작업 분할·스케줄링·동기화·결과 병합 비용이 추가되기 때문이다. 공유 락과 부하 불균형으로 일부 코어가 기다릴 수도 있다. 먼저 병렬 가능한 비율과 가장 긴 작업을 측정해야 한다.

## 12. 1~2분 확장답변

> 동시성은 여러 작업을 독립적으로 진행할 수 있게 구성하는 것이고 병렬성은 여러 코어에서 실제로 동시에 실행하는 것입니다. 비동기 I/O는 대기 시간을 활용하며 CPU 작업 병렬화와 목적이 다릅니다. 운영체제는 제한된 자원을 보호하면서 여러 작업을 진행시키고, 대기와 실행 상태를 전환합니다. 이 과정에는 스케줄링과 캐시 지역성 손실 같은 비용이 있습니다. 게임 서버에서는 I/O 대기와 CPU 계산을 구분하고, 공유 상태 범위를 줄이며, 평균값뿐 아니라 락 대기와 꼬리 지연을 함께 관찰해야 합니다.

## 13. 핵심 요약

- 동시성(Concurrency)은 여러 작업이 겹친 시간에 진행되는 구조이고, 병렬성(Parallelism)은 여러 작업이 실제로 동시에 실행되는 상태이다.
- 필요한 이유는 제한된 자원의 보호와 효율적 사용이다.
- 공유 범위와 실행 단위를 구분해야 한다.
- 동시 실행에는 전환과 동기화 비용이 따른다.
- 게임 서버에서는 지표와 꼬리 지연으로 실제 병목을 확인한다.
- 병렬화의 효과는 순차 구간, 작업 분할, 동기화와 부하 균형에 제한된다.
