# 11. TLB와 CPU Cache

> 게임 서버·백엔드 개발자를 위한 CS 면접 교재

## 학습 목표

- 정의와 필요성을 설명할 수 있다.
- 핵심 동작과 비교 개념을 설명할 수 있다.
- 게임 서버 성능 진단에 적용할 수 있다.

## 1. 개요

TLB는 최근 주소 변환을, CPU Cache는 최근 명령과 데이터를 저장한다.

TLB(Translation Lookaside Buffer)는 가상 페이지 번호에서 물리 프레임 번호로의 변환 결과를 캐시한다. CPU 캐시는 메모리에서 읽은 명령과 실제 데이터의 복사본을 캐시 라인 단위로 보관한다. 둘 다 느린 하위 계층 접근을 줄이는 하드웨어 캐시지만 무엇을 저장하는지가 다르다.

TLB 미스는 주소 변환을 찾기 위한 페이지 테이블 탐색을 만들고, CPU 캐시 미스는 필요한 데이터나 명령을 하위 캐시 또는 DRAM에서 가져오게 한다. TLB 미스가 곧 페이지 폴트는 아니며 CPU 캐시 미스가 디스크 접근을 뜻하지도 않는다.

## 2. 왜 필요한가

Page Table 탐색과 DRAM 접근 지연을 줄인다. 추상화의 편리함에도 실제 전환과 메모리 비용은 남는다.

CPU는 한 명령을 처리하는 동안 여러 메모리 접근이 필요할 수 있는데 DRAM은 CPU 연산보다 훨씬 느리다. 가상 주소를 사용할 때마다 다단계 페이지 테이블을 메모리에서 읽고, 이어서 실제 데이터까지 DRAM에서 읽는다면 지연이 누적된다. TLB가 변환을, L1·L2·L3 캐시가 명령과 데이터를 가까이 보관해 이 간격을 줄인다.

캐시는 용량이 작을수록 빠르고 코어 가까이에 둘 수 있다. 그래서 하나의 거대한 캐시보다 작고 빠른 L1, 더 크지만 느린 L2와 L3 같은 계층을 사용한다. 세부 공유 구조와 크기는 CPU 아키텍처마다 다르므로 일반적인 계층 원리를 설명하되 특정 수치를 보편적인 사실처럼 외우지 않는다.

## 3. 핵심 동작 원리

```text
Virtual Address
      |
      v
     TLB ── miss ──> Page Table Walk
      |
Physical Address
      |
      v
 L1 Cache → L2 Cache → L3 Cache → DRAM
   빠름·작음                      느림·큼
```
TLB는 주소 변환이고 Cache는 데이터다. 지역성이 높을수록 효과적이며 False Sharing은 Cache Line 경쟁을 만든다. 보호, 변환, Cache 계층 중 어디서 대기하는지 구분한다.

### TLB Hit와 Miss

TLB에 가상 페이지 변환이 있으면 물리 주소를 빠르게 구성한다. 없으면 페이지 테이블을 탐색한다. 페이지 테이블에 유효한 매핑이 있다면 TLB를 채우고 접근을 계속하므로 페이지 폴트는 발생하지 않는다. 매핑이 없거나 권한 처리가 필요할 때 페이지 폴트가 발생한다.

프로세스가 바뀌면 같은 가상 주소의 의미가 달라질 수 있다. 하드웨어는 주소 공간 식별자 같은 태그로 여러 프로세스의 TLB 항목을 구분하거나 필요한 항목을 무효화한다. 페이지 매핑을 변경하면 관련 코어의 오래된 TLB 항목도 무효화해야 하며, 다중 코어의 TLB Shootdown은 매핑 변경이 잦을 때 비용이 될 수 있다.

큰 페이지는 한 TLB 항목이 더 넓은 메모리 범위를 표현하게 해 TLB 도달 범위(Reach)를 늘린다. 대형 연속 데이터에서 미스를 줄일 수 있지만 내부 단편화와 메모리 관리 부담이 늘 수 있다.

### Cache Line과 계층

CPU 캐시는 보통 바이트 하나가 아니라 고정 크기 캐시 라인 단위로 데이터를 가져온다. 배열의 한 원소를 읽으면 인접 원소도 같은 라인에 들어올 수 있어 순차 접근이 유리하다. 캐시 라인의 정확한 크기와 정책은 하드웨어마다 다르지만 64바이트가 흔한 예다.

```text
Array: [0][1][2][3][4][5][6][7]...
        └──── 한 Cache Line ────┘

순차 접근: 이미 가져온 Line의 이웃 Data 사용
무작위 Pointer 접근: 다른 Line을 반복해서 가져올 가능성
```

캐시가 가득 차면 교체 정책에 따라 기존 라인을 내보낸다. 여러 주소가 같은 제한된 캐시 집합에 몰리면 전체 용량이 남아 보여도 충돌 미스가 날 수 있다. 면접에서는 필수 미스, 용량 미스, 충돌 미스라는 관점을 짧게 소개할 수 있다.

### 시간 지역성과 공간 지역성

- 시간 지역성(Temporal Locality): 최근 사용한 데이터가 곧 다시 사용될 가능성이 높다.
- 공간 지역성(Spatial Locality): 접근한 주소 근처의 데이터도 곧 사용할 가능성이 높다.

루프에서 같은 룩업 테이블을 반복 사용하면 시간 지역성이 높다. 연속 배열을 앞에서부터 순회하면 공간 지역성이 높다. 연결 리스트는 각 노드가 힙에 흩어질 수 있어 같은 논리 원소 수라도 배열보다 캐시 효율이 낮을 수 있다.

### Cache Coherence

여러 코어가 각자 캐시를 가지면 한 코어가 쓴 값을 다른 코어의 오래된 캐시 복사본과 일관되게 만들어야 한다. 캐시 일관성 프로토콜은 동일한 메모리 위치의 캐시 라인 상태를 조정한다. 그러나 캐시 일관성이 프로그램의 복합 연산 원자성과 원하는 관찰 순서를 자동으로 보장하는 것은 아니다. 언어의 락과 원자 연산이 여전히 필요하다.

한 코어가 공유 라인에 쓰면 다른 코어의 복사본이 무효화되고 소유권이 이동할 수 있다. 여러 코어가 같은 라인을 자주 쓰면 실제 데이터 계산보다 이 소유권 전달에 많은 시간을 쓴다.

### False Sharing

서로 다른 스레드가 논리적으로 독립된 변수에 쓰더라도 두 변수가 같은 캐시 라인에 있으면 라인 전체의 소유권이 코어 사이를 오갈 수 있다. 이를 거짓 공유(False Sharing)라고 한다.

```text
한 Cache Line
┌───────────────────────────────────┐
│ Counter A (Core 0) | Counter B (Core 1) │
└───────────────────────────────────┘
          Line 소유권 Ping-Pong
```

스레드별 자주 쓰는 카운터를 캐시 라인 경계에 맞춰 분리하거나, 각 스레드가 로컬 집계한 뒤 낮은 빈도로 합쳐 완화할 수 있다. 패딩은 메모리 사용을 늘리고 런타임 배치 보장이 필요하므로 프로파일러로 확인한 뒤 적용한다.

### Prefetch와 Branch

하드웨어 프리페처는 규칙적인 접근 패턴을 감지해 필요한 데이터를 미리 가져올 수 있다. 순차 배열은 예측하기 쉽지만 무작위 포인터 추적은 어렵다. 소프트웨어 프리페치를 직접 넣는 최적화는 너무 이르거나 늦으면 효과가 없고 캐시 대역폭을 낭비할 수 있다.

분기 예측 실패도 파이프라인 비용을 만들지만 CPU 데이터 캐시와는 다른 메커니즘이다. 성능 프로파일에서 캐시 미스, TLB 미스와 분기 미스를 구분한다.

## 4. 쉬운 예시

TLB와 CPU Cache에서는 같은 결과의 코드라도 연속 메모리 순회와 흩어진 객체 접근은 실제 시간이 다르다. 데이터 수명과 호출 횟수를 함께 본다.

백만 개 플레이어의 `health`만 매 틱 갱신한다고 하자. 플레이어 객체가 큰 객체 그래프에 흩어져 있으면 필요한 값마다 다른 캐시 라인을 불러올 수 있다. 자주 함께 계산하는 필드를 연속 배열로 모으면 한 라인에서 여러 플레이어 값을 읽고 프리페치를 활용하기 쉽다.

반대로 모든 필드를 하나의 구조체 배열에 넣으면 현재 시스템이 쓰지 않는 이름, 장비와 메타데이터까지 캐시에 실릴 수 있다. AoS(Array of Structures)와 SoA(Structure of Arrays) 중 어느 것이 좋은지는 접근 패턴에 달려 있다.

```text
AoS: [Pos,Hp,Name][Pos,Hp,Name][Pos,Hp,Name]
SoA: [Pos][Pos][Pos]  [Hp][Hp][Hp]  [Name][Name][Name]
```

위치만 일괄 갱신하면 SoA가 유리할 수 있고 한 플레이어의 모든 필드를 함께 읽으면 AoS가 단순하고 유리할 수 있다.

## 5. 비슷한 개념과 비교

| 관점 | 역할 | 비용 |
|---|---|---|
| OS 추상화 | 보호·자원 관리 | 전환 |
| 메모리 | 주소·수명 관리 | Fault·할당 |
| 하드웨어 | 접근 가속 | Cache Miss |

| 구분 | TLB | CPU Cache | Page Cache |
|---|---|---|---|
| 저장 대상 | 주소 변환 | 명령·메모리 Data | File 내용 Page |
| 관리 중심 | CPU·MMU | CPU Hardware | OS Kernel |
| Miss 결과 | Page Table Walk | 하위 Cache·DRAM 접근 | 저장장치 Read 가능 |
| 관련 최적화 | Huge Page·Working Set | 지역성·Data 배치 | I/O 패턴·Memory 압력 |

Page Cache는 운영체제가 파일 데이터를 RAM에 보관하는 캐시다. CPU 캐시보다 훨씬 상위 소프트웨어 계층이며 CPU가 파일 데이터를 사용할 때 그 메모리 역시 최종적으로 CPU 캐시를 거친다.

## 6. 장점과 단점

TLB와 CPU Cache에서는 보호와 추상화는 안정성을 높이지만 Fault, Miss, System Call과 할당 지연을 만든다. 측정된 병목만 최적화한다.

캐시는 프로그램 수정 없이 평균 접근 시간을 크게 줄이지만 용량이 제한되고 성능이 데이터 배치와 작업 집합에 민감해진다. 멀티코어에서는 일관성 트래픽도 발생한다. 캐시 친화적 최적화는 처리량을 높일 수 있지만 자료구조 복잡도와 메모리 사용을 늘릴 수 있으므로 실제 병목과 유지보수 비용을 비교한다.

## 7. 게임 서버·백엔드 실무 예시

연속 배열 순회로 지역성을 높이고 스레드별 카운터의 False Sharing을 피한다. 평균 CPU뿐 아니라 할당률, RSS, Fault, 호출 수와 p99를 본다.

CPU가 100%인데 함수별 명령 수 대비 진행이 적다면 하드웨어 성능 카운터로 캐시 미스, TLB 미스, 메모리 대역폭과 코어별 사용률을 확인한다. 단순 벽시계 프로파일은 어느 함수에서 시간이 쓰였는지는 보여도 메모리 병목의 이유까지 직접 설명하지 못할 수 있다.

ECS(Entity Component System) 형태의 게임 데이터 배치는 같은 컴포넌트를 연속 처리해 지역성을 높일 수 있다. 하지만 엔티티 이동에 따른 배열 재배치와 복잡성이 있다. 데이터 지향 설계라는 이름만으로 도입하지 않고 실제 틱의 Hot Path와 접근 필드를 측정한다.

공유 통계 카운터 하나를 모든 네트워크 스레드가 매 패킷 증가시키면 원자 연산 자체가 짧아도 캐시 라인이 코어 사이를 이동한다. 스레드별 카운터에 누적하고 모니터링 시 합치면 경쟁을 줄일 수 있다. 이 값이 정확한 용량 제한에 쓰인다면 지연된 집계가 허용되는지 별도로 판단한다.

## 8. 자주 하는 오해
- 가상 주소와 물리 사용량을 같다고 본다.
- Heap은 언제나 느리다고 단정한다.
- Page Fault는 모두 디스크 I/O라고 본다.
- TLB와 CPU Cache를 혼동한다.
- System Call과 Context Switch를 같다고 본다.
- TLB Miss는 항상 Page Fault라고 생각한다.
- Cache Coherence가 Data Race까지 해결한다고 본다.
- 연속 배열은 모든 접근 패턴에서 항상 빠르다고 단정한다.
- False Sharing은 같은 변수를 공유할 때만 생긴다고 생각한다.

## 9. 면접 질문
### Q1. 핵심 개념은 무엇인가요?
TLB는 최근 주소 변환을, CPU Cache는 최근 명령과 데이터를 저장한다.
### Q2. 왜 필요한가요?
Page Table 탐색과 DRAM 접근 지연을 줄인다.
### Q3. 실무 적용은 무엇인가요?
연속 배열 순회로 지역성을 높이고 스레드별 카운터의 False Sharing을 피한다.

### Q4. TLB Miss와 Page Fault의 차이는 무엇인가요?

TLB Miss는 변환 캐시에 항목이 없어 페이지 테이블을 탐색하는 사건이다. 페이지 테이블에 유효한 매핑이 있으면 Fault 없이 끝난다. Page Fault는 현재 매핑이나 권한으로 메모리 접근을 완료할 수 없어 커널 처리가 필요한 사건이다.

### Q5. False Sharing은 무엇인가요?

여러 코어가 서로 다른 변수에 쓰지만 그 변수들이 같은 캐시 라인에 있어 라인 소유권이 계속 이동하는 현상이다. 데이터상 공유가 없어도 캐시 단위가 더 크기 때문에 성능 저하가 생긴다.

### Q6. 시간 지역성과 공간 지역성의 차이는 무엇인가요?

시간 지역성은 최근 사용한 데이터를 곧 다시 사용하는 성질이고, 공간 지역성은 접근한 주소 주변 데이터를 곧 사용하는 성질이다. 반복 조회와 연속 배열 순회가 각각 대표 예다.
