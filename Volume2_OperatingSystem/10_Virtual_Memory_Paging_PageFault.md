# 10. Virtual Memory, Paging, Page Fault

> 게임 서버·백엔드 개발자를 위한 CS 면접 교재

## 학습 목표

- 정의와 필요성을 설명할 수 있다.
- 핵심 동작과 비교 개념을 설명할 수 있다.
- 게임 서버 성능 진단에 적용할 수 있다.

## 1. 개요

가상 메모리는 독립 주소 공간을 제공하고 Paging은 Page를 물리 Frame에 매핑하며 Page Fault는 현재 매핑으로 처리할 수 없는 접근이다.

가상 메모리(Virtual Memory)는 프로세스가 사용하는 주소를 실제 RAM 주소와 분리하는 추상화다. 페이징(Paging)은 가상 주소 공간과 물리 메모리를 고정 크기 블록인 페이지(Page)와 프레임(Frame)으로 나눠 매핑한다. 페이지 폴트(Page Fault)는 CPU가 현재 페이지 테이블 상태와 권한만으로 완료할 수 없는 메모리 접근을 감지해 운영체제에 제어를 넘기는 예외다.

페이지 폴트가 곧 오류라는 뜻은 아니다. 아직 물리 페이지가 연결되지 않은 정상적인 첫 접근일 수도 있고, 파일 데이터를 읽어 와야 할 수도 있으며, 접근 권한 위반으로 프로세스를 종료해야 할 수도 있다.

## 2. 왜 필요한가

격리, 연속 주소 추상화와 요구 페이징을 제공한다. 추상화의 편리함에도 실제 전환과 메모리 비용은 남는다.

프로세스마다 독립적인 가상 주소 공간을 주면 같은 가상 주소를 사용해도 서로 다른 물리 메모리에 연결할 수 있다. 다른 프로세스의 메모리를 임의로 읽거나 쓰기 어렵게 하고 페이지별 읽기·쓰기·실행 권한을 적용한다. 프로그램은 물리 RAM의 빈 연속 구간을 직접 찾지 않고 연속된 가상 주소를 사용할 수 있다.

실행 파일 전체와 예약한 메모리를 즉시 RAM에 올릴 필요도 없다. 실제 접근한 페이지에만 물리 메모리를 연결하는 요구 페이징(Demand Paging)은 시작 시간과 물리 메모리 사용을 줄인다. 파일 매핑, 프로세스 간 공유 메모리, Copy-on-Write도 페이지 매핑을 이용해 구현할 수 있다.

## 3. 핵심 동작 원리

```text
Virtual Address
  ├─ Virtual Page Number ──> TLB ──hit──> Physical Frame Number
  │                           │
  │                           miss
  │                           v
  │                      Page Table Walk
  └─ Offset ───────────────────────────────> Physical Address

Page Table에 현재 처리 가능한 Mapping 없음
                    ↓
               Page Fault
                    ↓
       OS가 Mapping 보완 또는 접근 거부
```

가상 주소는 가상 페이지 번호와 페이지 내부 오프셋으로 나뉜다. 페이지 테이블은 가상 페이지가 어느 물리 프레임에 연결되는지와 Present, Read/Write, User/Supervisor 같은 상태·권한 정보를 가진다. 오프셋은 변환 뒤에도 유지된다.

페이지 테이블 자체도 메모리에 있으므로 주소 변환마다 여러 번 메모리를 읽으면 느리다. TLB(Translation Lookaside Buffer)가 최근 주소 변환을 캐시한다. TLB 미스는 하드웨어나 운영체제가 페이지 테이블을 탐색해 해결할 수 있으며, 유효한 매핑이 있다면 페이지 폴트와는 다르다.

### 다단계 페이지 테이블

큰 가상 주소 공간의 모든 페이지에 단일 거대한 표 항목을 미리 만들면 메모리가 낭비된다. 다단계 페이지 테이블은 주소를 여러 인덱스로 나눠 실제 사용되는 하위 표만 만든다. 주소 변환 시 여러 단계 탐색이 필요하지만 희소한 주소 공간의 관리 메모리를 줄인다. TLB가 반복 탐색 비용을 완화한다.

### Page Fault 처리 흐름

```text
1. CPU가 Memory Access 수행
2. Page Table 상태·권한으로 처리 불가 → Fault
3. Kernel이 Fault 주소와 원인을 검사
4-a. 합법적 첫 접근: 0으로 채운 Frame 할당
4-b. File/Swap 데이터 필요: I/O 후 Frame 연결
4-c. Copy-on-Write 쓰기: 개인 Frame 복사 후 연결
4-d. 불법 주소·권한: Process에 오류 전달 또는 종료
5. 정상 처리라면 중단된 명령을 다시 실행
```

Minor Fault는 필요한 데이터가 이미 메모리에 있거나 새 0 페이지 할당처럼 저장장치 I/O 없이 처리되는 경우를 가리킨다. Major Fault는 파일이나 Swap에서 데이터를 읽는 저장장치 I/O가 필요해 지연이 훨씬 클 수 있다. 운영체제별 지표 정의에는 차이가 있을 수 있으므로 도구 문서를 확인한다.

불법 포인터 접근도 페이지 폴트를 일으킬 수 있지만 운영체제가 합법적인 매핑으로 복구하지 못한다. Unix 계열에서는 프로세스에 `SIGSEGV` 같은 신호가 전달될 수 있고 Windows에서는 접근 위반 예외가 발생할 수 있다. “Page Fault는 가상 메모리의 정상 기능이므로 항상 복구된다”는 설명은 틀리다.

### 요구 페이징과 Page 교체

물리 프레임이 부족하면 운영체제는 덜 필요하다고 판단한 페이지를 회수한다. 변경되지 않은 파일 기반 페이지는 버리고 나중에 파일에서 다시 읽을 수 있다. 수정된 익명 페이지는 Swap 같은 보조 저장소에 기록해야 할 수 있다. 실제 교체 알고리즘은 접근 빈도와 최근성을 근사해 Working Set을 유지하려 한다.

Working Set은 한 시간 구간에 프로세스가 활발히 사용하는 페이지 집합이다. 전체 활발한 집합이 물리 메모리보다 크면 페이지를 들여오자마자 다른 필요한 페이지를 내보내는 일이 반복될 수 있다. 이를 Thrashing이라고 하며 CPU보다 Page Fault와 저장장치 I/O에 시간을 쓰게 된다.

```text
요청 처리 → Page In → 다른 Page 퇴출 → 곧 다시 필요 → Page In 반복
                         ↑                         |
                         └──── Thrashing ─────────┘
```

### Copy-on-Write

`fork()` 직후 부모와 자식이 같은 물리 페이지를 읽기 전용으로 공유하고, 어느 쪽이 쓰려고 할 때 Fault를 발생시켜 개인 복사본을 만드는 방식이 Copy-on-Write다. 복제 직후 전체 메모리를 복사하지 않아도 된다. 파일 매핑과 스냅샷 계열 기능에도 비슷한 원리가 활용될 수 있다.

Copy-on-Write는 복사를 없애는 것이 아니라 실제 쓰기까지 미룬다. 큰 프로세스를 복제한 뒤 양쪽이 대부분의 페이지를 수정하면 메모리와 Fault 비용이 결국 발생한다.

### 큰 Page

페이지가 크면 같은 메모리 범위를 표현하는 페이지 테이블 항목과 TLB 항목 수를 줄일 수 있다. 반면 작은 양만 사용해도 큰 단위로 메모리를 차지해 내부 단편화가 늘고 할당·회수 유연성이 낮아질 수 있다. Huge Page는 큰 연속 Working Set에서 TLB 미스를 줄일 가능성이 있지만 실제 접근 패턴과 운영 부담을 측정한 뒤 적용한다.

## 4. 쉬운 예시

Virtual Memory, Paging, Page Fault에서는 같은 결과의 코드라도 연속 메모리 순회와 흩어진 객체 접근은 실제 시간이 다르다. 데이터 수명과 호출 횟수를 함께 본다.

게임 서버가 10GB 주소 공간을 예약했지만 실제로 2GB만 접근했다면 모든 10GB가 RAM을 점유하지 않을 수 있다. 접근하지 않은 페이지는 물리 프레임이 연결되지 않을 수 있기 때문이다. 반대로 2GB의 활발한 데이터가 메모리 압박으로 계속 Swap 된다면 예약 크기는 작아 보여도 큰 지연이 발생할 수 있다.

서버 시작 후 처음 맵 데이터를 순회할 때 Minor 또는 Major Fault가 집중되어 첫 매치만 느릴 수 있다. 준비 단계에서 필요한 데이터를 미리 읽어 Working Set을 데우거나, 실제 트래픽을 받기 전 준비 상태를 확인할 수 있다. 다만 무조건 전체 데이터를 미리 만지면 시작 시간과 메모리 사용이 늘어난다.

## 5. 비슷한 개념과 비교

| 관점 | 역할 | 비용 |
|---|---|---|
| OS 추상화 | 보호·자원 관리 | 전환 |
| 메모리 | 주소·수명 관리 | Fault·할당 |
| 하드웨어 | 접근 가속 | Cache Miss |

| 사건 | 찾는 대상 | 일반 처리 | 비용 관점 |
|---|---|---|---|
| CPU Cache Miss | 최근 Data·명령 | 하위 Cache 또는 RAM 접근 | 하드웨어 지연 |
| TLB Miss | 가상→물리 주소 변환 | Page Table Walk | Fault 없이 해결 가능 |
| Minor Page Fault | 현재 Mapping 보완 | Frame 연결·COW 등 | Kernel 진입, Disk I/O 없음 |
| Major Page Fault | 저장장치의 Page 필요 | File·Swap Read | 큰 지연 가능 |
| Protection Fault | 허용되지 않은 접근 | 오류 전달·종료 | 정상 Paging과 구분 |

세그멘테이션(Segmentation)은 논리적 가변 크기 구간을 기반으로 주소를 관리하는 방식이고 페이징은 고정 크기 단위를 사용한다. 현대 범용 시스템의 사용자 주소 공간 설명에서는 페이징이 중심이지만 아키텍처의 세부 주소 변환 기능은 다를 수 있다.

## 6. 장점과 단점

Virtual Memory, Paging, Page Fault에서는 보호와 추상화는 안정성을 높이지만 Fault, Miss, System Call과 할당 지연을 만든다. 측정된 병목만 최적화한다.

장점은 프로세스 격리, 간단한 주소 공간, 페이지별 보호, 요구 할당과 공유다. 단점은 페이지 테이블 메모리, TLB 미스와 Fault 처리 비용, 메모리 압박 시 예측하기 어려운 저장장치 지연이다. 가상 주소 공간이 넓다는 사실이 물리 메모리가 무한하다는 뜻은 아니다.

## 7. 게임 서버·백엔드 실무 예시

RSS, Fault, Swap과 working set을 관찰하고 무제한 캐시를 막는다. 평균 CPU뿐 아니라 할당률, RSS, Fault, 호출 수와 p99를 본다.

게임 서버의 p99 틱 지연이 급증할 때 같은 시간의 Major Fault, Swap In/Out, 메모리 압박과 디스크 지연을 확인한다. Minor Fault 증가는 새 메모리 대량 접근이나 Copy-on-Write일 수 있어 Major Fault와 구분한다. RSS만 계속 늘어난다면 캐시 상한, 객체 수명, 메모리 매핑과 네이티브 버퍼를 분리한다.

운영 서버는 가능한 한 활발한 Working Set이 RAM 안에 머물도록 용량을 계획한다. Swap을 무조건 끄는 것이 모든 환경의 정답은 아니지만, 지연에 민감한 틱 스레드가 Major Fault를 만나지 않도록 메모리 상한과 과부하 거절을 둔다. 컨테이너에서는 호스트 전체 메모리와 별개로 cgroup 제한, OOM 종료 이벤트와 메모리 압박 지표를 확인한다.

메모리 매핑 파일은 대형 맵이나 읽기 전용 데이터 접근을 단순하게 할 수 있지만 접근 순간 Fault와 I/O가 발생할 수 있다. 파일 매핑이 곧 전체 파일의 즉시 RAM 적재를 뜻하지 않는다. 배포 직후와 장애 복구 시 Cold Cache 성능을 따로 시험한다.

## 8. 자주 하는 오해
- 가상 주소와 물리 사용량을 같다고 본다.
- Heap은 언제나 느리다고 단정한다.
- Page Fault는 모두 디스크 I/O라고 본다.
- TLB와 CPU Cache를 혼동한다.
- System Call과 Context Switch를 같다고 본다.
- TLB Miss가 곧 Page Fault라고 생각한다.
- 가상 메모리는 RAM 부족분을 Disk로 쓰는 기능만이라고 본다.
- 주소 공간을 예약하면 같은 크기의 물리 메모리를 즉시 사용한다고 본다.
- Copy-on-Write는 복사 비용을 영원히 없앤다고 생각한다.

## 9. 면접 질문
### Q1. 핵심 개념은 무엇인가요?
가상 메모리는 독립 주소 공간을 제공하고 Paging은 Page를 물리 Frame에 매핑하며 Page Fault는 현재 매핑으로 처리할 수 없는 접근이다.
### Q2. 왜 필요한가요?
격리, 연속 주소 추상화와 요구 페이징을 제공한다.
### Q3. 실무 적용은 무엇인가요?
RSS, Fault, Swap과 working set을 관찰하고 무제한 캐시를 막는다.

### Q4. Page Fault 처리 과정을 설명해 주세요.

CPU가 현재 매핑이나 권한으로 접근을 완료할 수 없으면 커널에 제어를 넘긴다. 커널은 합법적인 요구 할당, 파일 읽기, Copy-on-Write라면 페이지를 준비하고 명령을 재실행한다. 불법 주소나 권한 위반이면 프로세스에 오류를 전달한다.

### Q5. Minor Fault와 Major Fault의 차이는 무엇인가요?

Minor Fault는 저장장치 읽기 없이 메모리 매핑을 보완할 수 있는 경우다. Major Fault는 파일이나 Swap에서 페이지를 읽어야 해 큰 I/O 지연이 발생할 수 있다.

### Q6. Thrashing은 무엇인가요?

활발히 사용하는 페이지 집합이 물리 메모리에 맞지 않아 필요한 페이지를 계속 들이고 곧 필요한 다른 페이지를 내보내는 현상이다. Fault와 Swap I/O가 반복되어 처리량과 응답 시간이 크게 나빠진다.
