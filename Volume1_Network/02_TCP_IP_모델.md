# 02. TCP/IP 모델

> 게임 서버·백엔드 개발자를 위한 CS 면접 교재

## 학습 목표

이 문서를 읽은 뒤 다음을 설명할 수 있어야 한다.

- TCP/IP 모델의 네 계층과 대표 프로토콜을 설명할 수 있다.
- 애플리케이션 데이터가 인터넷을 거쳐 다른 프로세스에 전달되는 흐름을 설명할 수 있다.
- IP 주소, 포트 번호, MAC 주소가 각각 어디에서 왜 필요한지 구분할 수 있다.
- TCP/IP 모델과 OSI 7계층의 관계를 면접 답변으로 정리할 수 있다.

---

## 1. 개요

TCP/IP 모델은 인터넷 통신에 필요한 기능을 **응용, 전송, 인터넷, 네트워크 접근 계층**으로 나눈 프로토콜 중심의 계층 모델이다.

이름에는 TCP와 IP가 들어가지만 두 프로토콜만 의미하지 않는다. TCP/IP 프로토콜 모음(Protocol Suite)에는 HTTP, DNS, TCP, UDP, IP, ICMP, Ethernet처럼 인터넷 통신에 함께 쓰이는 여러 프로토콜이 포함된다.

| 계층 | 핵심 역할 | 대표 프로토콜·기술 |
|---|---|---|
| 응용 계층(Application) | 애플리케이션이 사용할 통신 규칙과 데이터 형식 정의 | HTTP, DNS, TLS, 게임 메시지 프로토콜 |
| 전송 계층(Transport) | 종단 프로세스 간 데이터 전달 | TCP, UDP, 포트 번호 |
| 인터넷 계층(Internet) | 여러 네트워크를 지나 목적지 호스트까지 전달 | IPv4, IPv6, ICMP, 라우터 |
| 네트워크 접근 계층(Network Access) | 현재 링크에서 프레임을 실제 신호로 전달 | Ethernet, Wi-Fi, MAC 주소 |

문헌에 따라 네트워크 접근 계층을 데이터 링크와 물리 계층으로 나눈 5계층 인터넷 모델을 사용하기도 한다. 계층 수보다 중요한 것은 각 계층의 책임이다. 이 문서에서는 실무에서 자주 쓰는 4계층 구분을 기준으로 설명한다.

## 2. 왜 필요한가

### 서로 다른 네트워크를 연결해야 한다

인터넷은 하나의 거대한 단일 네트워크가 아니다. 가정의 Wi-Fi, 회사의 Ethernet, 통신사 망, 데이터센터 네트워크처럼 서로 다른 기술로 구성된 네트워크들이 연결된 구조다.

IP는 하위 링크 기술의 차이를 감추고 공통 주소와 패킷 전달 방식을 제공한다. 애플리케이션은 중간 경로가 유선인지 무선인지 일일이 알지 않아도 목적지 IP로 데이터를 보낼 수 있다.

### 호스트가 아니라 프로세스까지 찾아가야 한다

IP 주소는 목적지 컴퓨터를 식별하지만 그 안에서 실행 중인 로그인 서버, 채팅 서버, 웹 서버 중 어느 프로세스가 데이터를 받을지는 정하지 못한다. 전송 계층은 포트(Port) 번호를 사용해 대상 프로세스를 구분한다.

### 애플리케이션마다 다른 전달 특성이 필요하다

결제 요청은 누락이나 중복을 엄격하게 다뤄야 한다. 반면 실시간 게임의 위치 갱신은 오래된 데이터를 재전송하기보다 최신 데이터를 빠르게 보내는 것이 나을 수 있다. 전송 계층에서 TCP와 UDP 같은 선택지를 제공하면 애플리케이션이 요구사항에 맞는 전달 방식을 선택할 수 있다.

### 계층별로 기술을 독립적으로 발전시킬 수 있다

응용 계층의 HTTP는 Ethernet뿐 아니라 Wi-Fi 위에서도 동작한다. IPv4에서 IPv6로 전환하더라도 애플리케이션의 핵심 비즈니스 규칙 전체를 다시 작성할 필요는 없다. 계층화는 아래 구현의 세부사항을 상위 계층에 직접 노출하지 않아 기술 조합과 교체를 쉽게 한다.

## 3. 핵심 동작 원리

### 3.1 응용 계층: 무엇을 주고받는가

응용 계층은 네트워크를 사용하는 프로그램 사이의 메시지 의미와 교환 규칙을 정의한다. 예를 들어 HTTP는 요청 메서드, 경로, 헤더, 응답 상태 코드를 정의한다. 게임 프로토콜은 로그인 요청에 계정 토큰을 넣고, 이동 메시지에 플레이어 식별자와 좌표를 넣는 식으로 정의할 수 있다.

이 계층에는 OSI 모델의 응용·표현·세션 계층 역할이 함께 포함되는 경우가 많다. 따라서 직렬화, 압축, 암호화, 애플리케이션 세션 관리가 응용 코드나 라이브러리에서 처리될 수 있다.

응용 계층은 전송 계층이 제공하는 소켓(Socket) 인터페이스를 통해 바이트를 보내고 받는다. TCP를 사용한다면 메시지 경계는 응용 프로토콜이 직접 정의해야 한다. 한 번의 `Send`와 한 번의 `Receive`가 일대일로 대응하지 않기 때문이다.

### 3.2 전송 계층: 어느 프로세스로 어떻게 전달하는가

전송 계층은 출발지와 목적지 프로세스 사이의 통신을 담당한다. 핵심 식별 정보는 포트 번호다.

TCP는 연결을 설정하고 바이트를 순서대로 전달한다. 손실된 데이터를 재전송하고, 수신자가 처리할 수 있는 양과 네트워크 혼잡 상태를 고려해 전송량을 조절한다. 대신 연결 관리와 재전송으로 인한 비용이 있다.

UDP는 연결 설정 없이 데이터그램을 보낸다. 순서, 도착, 중복 방지를 자체적으로 보장하지 않는다. 대신 헤더와 동작이 단순하고, 애플리케이션이 지연과 신뢰성 정책을 직접 설계하기 쉽다.

전송 계층은 응용 데이터를 필요한 단위로 나누고 헤더를 붙인다. 수신 측은 목적지 포트를 보고 적절한 소켓으로 데이터를 전달한다. 이를 다중화와 역다중화라고 한다. 여러 애플리케이션이 하나의 네트워크 인터페이스를 함께 사용할 수 있는 이유다.

### 3.3 인터넷 계층: 어느 호스트로 전달하는가

인터넷 계층의 핵심 프로토콜은 IP(Internet Protocol)다. IP는 출발지와 목적지 IP 주소를 패킷(Packet)에 담고, 여러 네트워크를 거쳐 목적지 호스트까지 전달할 기반을 제공한다.

라우터는 패킷의 목적지 IP 주소와 라우팅 테이블을 확인해 다음 홉(Next Hop), 즉 다음 전달 지점을 선택한다. 각 라우터는 전체 여정을 한 번에 처리하는 것이 아니라 자신이 아는 다음 경로로 패킷을 넘긴다.

IP는 최선형 전달(Best-effort Delivery)을 제공한다. 가능한 범위에서 패킷을 전달하지만 도착, 순서, 중복 방지를 보장하지 않는다. 필요한 신뢰성은 TCP나 응용 계층에서 보완한다.

ICMP는 IP 통신 중 발생한 오류와 진단 정보를 전달한다. `ping`이나 경로 진단에서 볼 수 있지만, ICMP 응답이 차단될 수도 있으므로 응답이 없다는 사실만으로 대상 서버가 중단되었다고 단정할 수는 없다.

### 3.4 네트워크 접근 계층: 다음 장비까지 어떻게 보내는가

네트워크 접근 계층은 현재 연결된 링크에서 데이터를 실제로 전달한다. Ethernet과 Wi-Fi가 대표 기술이다. 이 계층은 프레임(Frame)을 만들고, 링크에 맞는 물리 신호로 전송한다.

로컬 Ethernet에서는 MAC 주소가 프레임 전달에 사용된다. 송신 호스트가 같은 네트워크의 다른 호스트로 보낸다면 대상 호스트의 MAC 주소가 필요하다. 목적지가 다른 네트워크에 있다면 우선 기본 게이트웨이의 MAC 주소로 프레임을 보낸다.

라우터를 통과하면 링크 계층 프레임은 구간마다 새로 만들어진다. MAC 주소는 현재 링크의 전달 대상을 가리키며, 인터넷 종단까지 그대로 유지되는 주소가 아니다. 반면 IP 패킷의 목적지 주소는 일반적으로 최종 호스트를 나타낸다. NAT 같은 장비가 있으면 IP 주소와 포트가 중간에 변환될 수 있다.

### 3.5 캡슐화와 전달 과정

게임 클라이언트가 TCP로 로그인 요청을 서버에 보낸다고 하자.

```text
게임 클라이언트
  응용: [LoginRequest]
            ↓ TCP 헤더 추가
  전송: [TCP | LoginRequest]
            ↓ IP 헤더 추가
  인터넷: [IP | TCP | LoginRequest]
            ↓ Ethernet 헤더·트레일러 추가
  접근: [Ethernet | IP | TCP | LoginRequest | FCS]
            ↓
        비트 신호 전송
            ↓
  스위치 → 라우터 → ... → 서버 네트워크
            ↓
서버에서 반대 순서로 헤더 확인·제거
            ↓
로그인 서버 프로세스가 LoginRequest 처리
```

이처럼 상위 계층 데이터에 하위 계층의 제어 정보가 붙는 과정을 캡슐화(Encapsulation)라고 한다. 서버에서는 각 계층이 자신에게 필요한 정보를 확인하고 제거한 뒤 상위 계층으로 넘긴다. 이를 역캡슐화(Decapsulation)라고 한다.

중간 라우터는 일반적으로 응용 데이터나 TCP 처리를 끝까지 수행하지 않는다. 들어온 프레임에서 IP 패킷을 꺼내 목적지 IP와 라우팅 정보를 확인하고, 다음 링크에 맞는 새 프레임으로 감싸 전달한다.

### 3.6 주소 세 가지를 구분하기

| 주소 | 주 계층 | 식별 대상 | 전달 범위의 관점 |
|---|---|---|---|
| 포트 번호 | 전송 | 호스트 안의 프로세스·소켓 | 종단 프로세스 간 통신 |
| IP 주소 | 인터넷 | 네트워크에 연결된 호스트·인터페이스 | 여러 네트워크를 거친 전달 |
| MAC 주소 | 네트워크 접근 | 현재 링크의 네트워크 인터페이스 | 한 링크 또는 로컬 구간의 전달 |

예를 들어 게임 서버의 `203.0.113.10:7777`에 접속한다면 IP 주소는 서버 호스트를, 포트 7777은 그 호스트의 게임 서버 프로세스를 찾는 데 사용된다. 클라이언트가 다른 네트워크에 있다면 첫 Ethernet 프레임의 목적지 MAC 주소는 서버가 아니라 기본 게이트웨이의 MAC 주소가 된다.

## 4. 쉬운 예시

플레이어가 채팅 메시지 `안녕하세요`를 전송한다고 하자.

1. 응용 계층은 메시지 타입, 채널 ID, 문자열 인코딩과 길이를 정한다.
2. 전송 계층은 TCP 연결의 출발지·목적지 포트와 순서 정보를 붙인다.
3. 인터넷 계층은 클라이언트와 채팅 서버의 IP 주소를 붙인다.
4. 네트워크 접근 계층은 현재 링크의 다음 장비로 보낼 프레임을 만든다.
5. 여러 라우터는 목적지 IP를 보고 패킷을 다음 네트워크로 전달한다.
6. 서버 운영체제는 목적지 포트를 기준으로 채팅 서버 소켓에 바이트를 전달한다.
7. 채팅 서버는 응용 프로토콜에 따라 채널과 문자열을 해석한다.

서버는 이후 권한과 금칙어를 검사하고 같은 채널의 사용자에게 메시지를 전달한다. TCP/IP 모델은 메시지가 프로세스까지 도달하는 통신 구조를 제공하지만, 채팅 규칙과 같은 비즈니스 로직은 응용 계층이 담당한다.

## 5. 비슷한 개념과 비교

### TCP/IP 모델과 OSI 7계층

| TCP/IP 모델 | OSI 모델의 대응 계층 | 주요 역할 |
|---|---|---|
| 응용 | 응용·표현·세션 | 메시지 의미, 표현, 대화 관리 |
| 전송 | 전송 | 프로세스 간 전달 |
| 인터넷 | 네트워크 | IP 주소와 라우팅 |
| 네트워크 접근 | 데이터 링크·물리 | 링크 프레임과 물리 전송 |

OSI 모델은 통신 기능을 설명하기 위한 참조 모델이며 역할을 일곱 단계로 세밀하게 구분한다. TCP/IP 모델은 실제 인터넷에서 사용되는 프로토콜 모음을 중심으로 계층을 묶는다. 따라서 네트워크를 학습하거나 장애 범위를 표현할 때는 OSI 용어를, 실제 인터넷 프로토콜의 관계를 설명할 때는 TCP/IP 모델을 자주 사용한다.

두 모델의 대응은 완벽한 일대일 관계가 아니다. 예를 들어 TLS의 암호화 기능은 OSI 관점에서 표현 계층 역할과 비슷하지만, TCP/IP 모델에서는 주로 응용 계층 영역에서 다룬다.

### TCP와 TCP/IP의 차이

TCP는 전송 계층의 개별 프로토콜이다. TCP/IP는 TCP, UDP, IP와 여러 응용·링크 프로토콜을 포함하는 전체 프로토콜 체계를 가리킨다. UDP를 사용하더라도 IP 위에서 통신한다면 TCP/IP 프로토콜 모음 안에서 동작한다고 표현할 수 있다.

## 6. 장점과 단점

### 장점

- 서로 다른 물리 네트워크를 IP라는 공통 방식으로 연결할 수 있다.
- 계층별 책임이 분리되어 애플리케이션과 하위 네트워크 기술을 독립적으로 개발하기 쉽다.
- TCP, UDP 등 요구사항에 맞는 전송 방식을 선택할 수 있다.
- 개방된 표준과 넓은 호환성을 기반으로 다양한 운영체제와 장비가 통신할 수 있다.
- 장애를 응용, 전송, IP 경로, 링크 문제로 나누어 분석할 수 있다.

### 단점과 고려 사항

- IP 자체는 패킷 도착과 순서를 보장하지 않으므로 상위 계층의 보완이 필요하다.
- 계층 경계가 실제 구현에서 완전히 분리되지는 않는다. 성능 최적화에는 MTU나 혼잡 같은 하위 계층 특성을 알아야 할 수 있다.
- TCP의 신뢰성은 편리하지만 재전송과 순서 보장 때문에 실시간 요구에서 지연이 커질 수 있다.
- IPv4 주소 부족을 완화하는 NAT는 주소와 포트를 변환하므로 외부에서 내부 호스트로 직접 연결하기 어렵게 만들 수 있다.

## 7. 게임 서버·백엔드 실무 예시

### 실시간 이동과 로그인에 다른 전송 방식을 사용하기

로그인 요청과 아이템 구매는 누락되거나 순서가 뒤바뀌면 처리 결과가 달라질 수 있다. 이런 데이터는 TCP를 사용하거나, 응용 계층에서 요청 식별자와 멱등성 같은 추가 안전장치를 둔다.

반면 초당 여러 번 전송하는 플레이어 위치는 오래된 위치가 늦게 도착해도 가치가 낮다. UDP를 선택하고 패킷에 시퀀스 번호를 넣어 오래된 갱신을 버리는 방식이 가능하다. 어느 경우든 IP가 목적지 호스트까지 전달하고, 포트가 서버 프로세스를 구분하는 기본 구조는 같다.

### 계층별 장애 분석

클라이언트가 게임 서버에 접속하지 못할 때 다음과 같이 확인할 수 있다.

```text
응용 계층: 프로토콜 버전, 인증 토큰, 메시지 형식이 맞는가?
     ↑
전송 계층: TCP 연결이 성립하는가? 포트가 열려 있는가?
     ↑
인터넷 계층: 목적지 IP와 라우팅이 맞는가? IP 차단이 있는가?
     ↑
접근 계층: 네트워크 인터페이스와 로컬 링크가 정상인가?
```

TCP 연결은 성공하지만 로그인 오류 응답이 온다면 하위 네트워크는 대체로 정상이며 응용 계층을 우선 조사할 수 있다. 반대로 연결 시간 초과가 발생한다면 서버의 포트 리스닝, 방화벽, 로드 밸런서, 라우팅 경로부터 확인하는 편이 효율적이다.

### 로드 밸런서가 있는 백엔드 요청

클라이언트가 API 도메인에 접속하면 DNS가 로드 밸런서의 IP를 알려 줄 수 있다. TCP 연결의 목적지 IP와 포트는 우선 로드 밸런서를 가리킨다. 4계층 로드 밸런서는 IP와 포트 정보를 기준으로, 7계층 로드 밸런서는 HTTP 경로나 헤더 같은 응용 정보를 기준으로 백엔드 서버를 선택할 수 있다.

이 사례는 같은 TCP/IP 통신에서도 중간 장비가 어느 계층의 정보를 읽는지에 따라 기능이 달라진다는 점을 보여 준다.

## 8. 자주 하는 오해

### “TCP/IP는 TCP와 IP 두 개만 뜻한다”

TCP/IP는 인터넷 통신에 사용되는 프로토콜 모음과 계층 구조를 뜻한다. UDP, ICMP, DNS, HTTP 등도 이 체계 안에서 함께 동작한다.

### “IP 주소가 있으면 서버 프로세스까지 찾을 수 있다”

IP 주소는 목적지 호스트를 식별한다. 호스트 안의 특정 프로세스는 전송 계층의 포트 번호로 구분한다.

### “MAC 주소는 목적지 서버까지 유지된다”

MAC 주소는 현재 링크에서 프레임을 전달하는 데 사용된다. 라우터를 지날 때 링크 프레임과 출발지·목적지 MAC 주소는 다음 구간에 맞게 바뀐다.

### “TCP를 쓰면 요청이 한 번만 처리된다”

TCP는 바이트 전달의 신뢰성을 제공하지만 비즈니스 요청의 정확히 한 번 실행을 보장하지 않는다. 응답이 유실되면 클라이언트가 요청을 다시 보낼 수 있으므로 결제나 아이템 지급은 요청 ID와 멱등성 처리가 필요하다.

### “UDP는 신뢰성을 구현할 수 없다”

UDP 자체는 신뢰성을 제공하지 않지만 애플리케이션이 필요한 메시지에만 확인 응답, 재전송, 순서 번호를 구현할 수 있다. 다만 이 설계에는 별도의 복잡성과 검증 비용이 따른다.

### “계층화되어 있으므로 상위 계층은 하위 계층을 몰라도 된다”

기능적 결합은 줄어들지만 성능과 안정성을 설계할 때는 하위 계층 제약을 알아야 한다. 예를 들어 큰 UDP 데이터그램은 MTU를 넘으면 IP 단편화 위험이 커진다.

## 9. 면접 질문

### Q1. TCP/IP 4계층을 설명해 주세요.

TCP/IP 모델은 응용, 전송, 인터넷, 네트워크 접근 계층으로 구성된다. 응용 계층은 메시지 의미와 통신 규칙을, 전송 계층은 포트 기반의 프로세스 간 전달을 담당한다. 인터넷 계층은 IP 주소와 라우팅으로 호스트 사이를 연결하며, 네트워크 접근 계층은 현재 링크에서 프레임과 신호를 전달한다.

### Q2. TCP/IP 모델에서 데이터가 전달되는 과정을 설명해 주세요.

응용 데이터가 전송 계층으로 내려가 TCP나 UDP 헤더가 붙고, 인터넷 계층에서 IP 헤더가 붙는다. 네트워크 접근 계층은 이를 현재 링크의 프레임으로 감싸 전송한다. 라우터는 목적지 IP를 보고 다음 경로로 전달하며, 수신 호스트는 반대 순서로 헤더를 제거해 대상 포트의 애플리케이션에 데이터를 넘긴다.

### Q3. IP 주소, 포트 번호, MAC 주소의 차이는 무엇인가요?

IP 주소는 여러 네트워크를 거쳐 목적지 호스트를 찾는 데 사용한다. 포트 번호는 그 호스트 안의 대상 프로세스나 소켓을 구분한다. MAC 주소는 현재 링크 구간에서 다음 네트워크 인터페이스로 프레임을 전달하는 데 사용한다.

### Q4. IP가 신뢰성을 보장하지 않는데 인터넷 통신이 가능한 이유는 무엇인가요?

IP는 최선형 전달만 제공하고, 필요한 신뢰성은 상위 계층이 보완한다. TCP는 순서 제어, 확인 응답, 재전송을 제공한다. UDP를 사용하는 애플리케이션은 데이터 특성에 따라 손실을 허용하거나 필요한 신뢰성 기능만 직접 구현한다.

### Q5. TCP/IP 모델과 OSI 모델의 차이는 무엇인가요?

OSI 모델은 통신 기능을 일곱 계층으로 나눈 개념적 참조 모델이다. TCP/IP 모델은 실제 인터넷 프로토콜 모음을 중심으로 보통 네 계층으로 설명한다. TCP/IP의 응용 계층은 OSI의 응용·표현·세션 계층을, 네트워크 접근 계층은 데이터 링크·물리 계층을 합친 것과 대략 대응한다.

## 12. 1~2분 확장답변

> TCP/IP 모델은 인터넷에서 실제 사용하는 프로토콜들의 역할을 응용, 전송, 인터넷, 네트워크 접근 계층으로 나눈 모델입니다. 응용 계층은 HTTP나 게임 메시지처럼 데이터의 의미와 교환 규칙을 정의합니다. 전송 계층은 포트 번호로 호스트 안의 프로세스를 구분하고, TCP의 신뢰성 있는 바이트 스트림이나 UDP의 단순한 데이터그램 전달을 제공합니다. 인터넷 계층의 IP는 출발지와 목적지 주소를 사용해 여러 네트워크를 지나 패킷을 전달하지만 도착이나 순서는 보장하지 않습니다. 네트워크 접근 계층은 Ethernet이나 Wi-Fi를 통해 현재 링크에서 프레임을 전송합니다. 송신할 때 각 계층의 헤더가 붙는 캡슐화가 일어나고, 수신 측에서는 반대로 제거됩니다. 이때 IP 주소는 목적지 호스트를, 포트는 프로세스를, MAC 주소는 현재 링크의 다음 인터페이스를 찾는 데 사용됩니다. OSI 모델이 역할을 일곱 단계로 설명하는 참조 모델이라면 TCP/IP 모델은 실제 인터넷 프로토콜 구성을 중심으로 네 계층으로 묶는다는 차이가 있습니다.

## 13. 핵심 요약

- TCP/IP 모델은 인터넷 통신 기능을 응용, 전송, 인터넷, 네트워크 접근 계층으로 나눈다.
- 응용 계층은 메시지 규칙을, 전송 계층은 포트 기반의 프로세스 간 전달을 담당한다.
- 인터넷 계층의 IP는 여러 네트워크를 거쳐 목적지 호스트까지 최선형 전달을 제공한다.
- 네트워크 접근 계층은 현재 링크에서 MAC 주소와 프레임을 사용해 데이터를 전달한다.
- IP 주소는 호스트, 포트 번호는 프로세스, MAC 주소는 현재 링크의 인터페이스를 구분한다.
- 송신 측은 계층별 헤더를 붙여 캡슐화하고 수신 측은 이를 역순으로 제거한다.
- OSI는 개념적 참조 모델이고 TCP/IP는 실제 인터넷 프로토콜 체계에 가까운 모델이다.

## 한 줄 정리

> TCP/IP 모델은 응용 메시지를 포트, IP 주소, 링크 기술의 역할로 나누어 서로 다른 네트워크의 목적지 프로세스까지 전달하는 인터넷의 기본 구조다.
