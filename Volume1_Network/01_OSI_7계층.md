# 01. OSI 7계층


## 학습 목표

이 문서를 읽은 뒤 다음을 설명할 수 있어야 한다.

- OSI(Open Systems Interconnection) 7계층이 필요한 이유와 각 계층의 핵심 역할(응용~물리)을 설명할 수 있다.
- 데이터가 송신 측에서 캡슐화되고 수신 측에서 역캡슐화되는 흐름을 설명할 수 있다.
- OSI 모델과 TCP/IP(Transmission Control Protocol/Internet Protocol) 모델의 차이를 설명하고 장애 원인을 계층별로 좁힐 수 있다.
- 게임 서버 접속 장애 시 물리·IP·포트·응용 계층 순서로 원인을 분리하는 방법을 설명할 수 있다.

---

## 1. 개요

OSI(Open Systems Interconnection) 7계층은 네트워크 통신 기능을 역할에 따라 일곱 단계로 나눈 **개념적 참조 모델**이다.

네트워크 통신에는 애플리케이션 메시지 형식, 데이터 표현, 연결 관리, 신뢰성 있는 전송, 경로 선택, 같은 네트워크 안에서의 전달, 전기·무선 신호 전송이 함께 필요하다. 이 기능을 하나로 묶으면 설계와 장애 분석이 어려워진다. OSI 모델은 각 기능의 책임과 계층 사이의 인터페이스를 구분해 문제를 다루기 쉽게 만든다.

위에서 아래로 계층은 다음과 같다.

| 계층 | 이름 | 핵심 역할 | 대표 예시 |
|---|---|---|---|
| 7 | 응용 계층(Application) | 사용자 애플리케이션에 네트워크 서비스 제공 | HTTP(HyperText Transfer Protocol), DNS(Domain Name System), 게임 애플리케이션 프로토콜 |
| 6 | 표현 계층(Presentation) | 데이터 형식 변환, 직렬화, 압축, 암호화 | JSON, UTF-8, TLS(Transport Layer Security)의 암호화 기능 |
| 5 | 세션 계층(Session) | 통신 세션의 설정, 유지, 종료 | 세션 관리, 체크포인트 |
| 4 | 전송 계층(Transport) | 프로세스 간 전송, 분할, 신뢰성·흐름 제어 | TCP(Transmission Control Protocol), UDP(User Datagram Protocol), 포트 |
| 3 | 네트워크 계층(Network) | 서로 다른 네트워크 사이의 주소 지정과 경로 선택 | IP(Internet Protocol), 라우터 |
| 2 | 데이터 링크 계층(Data Link) | 같은 링크 안에서 프레임 전달과 오류 검출 | Ethernet, MAC(Media Access Control) 주소, 스위치 |
| 1 | 물리 계층(Physical) | 비트를 전기·광·무선 신호로 전송 | 케이블, 광섬유, 전파, 허브 |

실제 프로토콜이 언제나 정확히 한 계층에만 들어맞는 것은 아니다. 예를 들어 TLS는 표현 계층의 암호화 역할을 수행하지만, 실제 인터넷에서는 응용 계층과 전송 계층 사이에서 사용된다고 설명하기도 한다. 따라서 계층 번호 암기보다 각 기능의 책임을 이해하는 것이 중요하다.

## 2. 왜 필요한가

### 복잡성을 나눌 수 있다

각 계층은 상위 계층에 서비스를 제공하고, 하위 계층의 구체적인 구현은 감춘다. 웹 서버 개발자는 광케이블에서 비트가 어떻게 표현되는지 몰라도 HTTP 응답을 보낼 수 있다. 애플리케이션은 전송 계층에 데이터를 넘기고, 아래 계층들이 실제 전달을 담당한다.

### 서로 다른 기술을 조합할 수 있다

계층 사이의 약속이 유지되면 한 계층의 기술을 바꾸어도 다른 계층 전체를 다시 설계할 필요가 없다. 같은 HTTP 요청을 유선 Ethernet이나 Wi-Fi를 통해 보낼 수 있는 것이 대표적이다. 아래쪽 전달 방식은 달라도 위쪽 애플리케이션의 동작은 유지된다.

### 장애 범위를 좁힐 수 있다

통신 실패를 계층 관점에서 확인하면 원인을 체계적으로 찾을 수 있다. 케이블 연결 문제인지, IP 경로 문제인지, TCP 포트 문제인지, HTTP 인증 문제인지 순서대로 구분할 수 있다. 실무에서는 이것이 OSI 모델의 가장 직접적인 가치 중 하나다.

## 3. 핵심 동작 원리

### 3.1 계층별 역할

**7계층 응용 계층**은 사용자가 이용하는 네트워크 기능과 가장 가깝다. HTTP 요청과 응답, DNS 이름 조회, 게임의 로그인·채팅 메시지처럼 애플리케이션이 이해하는 규칙을 정의한다. 응용 계층은 화면 자체가 아니라 프로그램이 네트워크를 이용하기 위한 프로토콜 계층이다.

**6계층 표현 계층**은 양쪽 시스템이 데이터를 같은 의미로 해석하도록 표현 방식을 맞춘다. 문자 인코딩, 객체 직렬화, 압축, 암호화와 복호화가 대표 역할이다. 게임 서버에서는 구조체를 바이트 배열로 직렬화하거나 정수의 바이트 순서를 맞추는 작업이 이 역할과 관련된다.

**5계층 세션 계층**은 통신 대화의 시작, 유지, 종료를 관리한다. 연결이 끊겼을 때 대화를 어디서 재개할지 같은 동기화 기능도 포함한다. 다만 현대 애플리케이션에서는 세션 기능을 응용 계층이나 라이브러리가 담당하는 경우가 많다.

**4계층 전송 계층**은 호스트 안의 특정 프로세스 사이에서 데이터를 전달한다. 포트 번호로 대상을 구분하고, 큰 데이터를 세그먼트로 나눈다. TCP는 순서 보장, 재전송, 흐름 제어 등을 제공한다. UDP는 이런 보장을 줄이는 대신 단순하고 지연 제어가 쉽다.

**3계층 네트워크 계층**은 IP 주소를 사용해 목적지 호스트가 있는 네트워크까지 패킷을 전달한다. 라우터는 목적지 IP와 라우팅 테이블을 보고 다음 전달 지점을 선택한다. 이 계층은 종단 간 경로를 다루지만 전송 성공 자체를 보장하지는 않는다.

**2계층 데이터 링크 계층**은 하나의 링크 또는 로컬 네트워크 구간에서 노드 간 데이터를 프레임 단위로 전달한다. Ethernet에서는 MAC 주소를 사용하고, 스위치는 MAC 주소 테이블을 바탕으로 프레임을 전달한다. 프레임의 오류 검출도 이 계층의 역할이다.

**1계층 물리 계층**은 0과 1을 실제 신호로 바꾸어 매체를 통해 보낸다. 커넥터, 전압, 주파수, 전송 속도 같은 물리적 특성을 다룬다.

### 3.2 캡슐화와 역캡슐화

송신 측에서는 상위 계층의 데이터가 아래 계층으로 내려가며 각 계층의 제어 정보가 붙는다. 이를 **캡슐화(Encapsulation)**라고 한다. 수신 측에서는 반대로 헤더를 확인하고 제거해 상위 계층으로 올린다. 이를 **역캡슐화(Decapsulation)**라고 한다.

```text
송신 애플리케이션                                  수신 애플리케이션
       |                                                    ^
       v                                                    |
[응용 데이터]                                           [응용 데이터]
       |                                                    ^
[TCP 헤더 | 데이터]          세그먼트                    TCP 헤더 제거
       |                                                    ^
[IP 헤더 | TCP 헤더 | 데이터] 패킷                       IP 헤더 제거
       |                                                    ^
[프레임 헤더 | IP 패킷 | 트레일러] 프레임               프레임 정보 제거
       |                                                    ^
       +------------ 물리 매체의 비트 신호 --------------->+
```

예를 들어 클라이언트가 로그인 요청을 보내면 응용 계층 메시지에 TCP 헤더, IP 헤더, Ethernet 프레임 정보가 차례로 붙는다. 서버는 이를 반대 순서로 해석한 뒤 최종 로그인 메시지를 애플리케이션에 전달한다.

계층에 따라 데이터 단위를 부르는 이름도 달라진다. 일반적으로 4계층 TCP 데이터는 **세그먼트**, UDP 데이터는 **데이터그램**, 3계층 데이터는 **패킷**, 2계층 데이터는 **프레임**, 1계층 데이터는 **비트**라고 부른다. 문맥에 따라 패킷을 넓은 의미로 사용하기도 한다.

### 3.3 계층 간 통신의 관점

논리적으로는 같은 계층끼리 프로토콜을 이용해 통신한다. 클라이언트의 TCP는 서버의 TCP와 순서 번호와 확인 응답을 주고받는다고 볼 수 있다. 실제 데이터는 클라이언트의 TCP가 직접 서버의 TCP로 건너가는 것이 아니라, 하위 계층과 네트워크 장비를 거쳐 전달된다.

중간 장비가 확인하는 계층도 다르다. 일반적인 스위치는 주로 2계층 정보를, 라우터는 3계층 정보를 사용한다. 로드 밸런서는 제품과 구성에 따라 4계층의 IP·포트 또는 7계층의 HTTP 정보까지 확인할 수 있다.

## 4. 쉬운 예시

게임 클라이언트가 `Attack(targetId=42)` 메시지를 서버에 보낸다고 하자.

1. 응용 계층은 공격 메시지의 타입과 필드를 정의한다.
2. 표현 계층 역할의 직렬화 코드는 메시지를 바이트 배열로 바꾼다.
3. 세션 관련 코드는 로그인된 플레이어의 연결 상태를 관리한다.
4. 전송 계층은 TCP라면 데이터를 세그먼트로 나누고 포트 번호와 순서 정보를 붙인다.
5. 네트워크 계층은 서버 IP를 목적지로 하는 패킷을 만든다.
6. 데이터 링크 계층은 현재 네트워크 구간에서 다음 장비로 보낼 프레임을 만든다.
7. 물리 계층은 프레임을 비트 신호로 전송한다.

서버는 반대 과정을 거쳐 바이트 배열을 공격 메시지로 복원한다. 그 뒤 서버 애플리케이션이 사거리, 재사용 대기시간, 대상의 생존 여부를 검증한다. OSI 모델은 전달 과정의 책임을 구분하지만, 게임 규칙 검증까지 대신하지는 않는다.

### 코드로 보는 계층별 역할

```java
// [응용 계층] 애플리케이션이 이해하는 메시지 구조
public record AttackPacket(short packetType, int targetId) {}

// [표현 계층] 직렬화 — 구조체를 바이트 배열로 변환
ByteBuffer buf = ByteBuffer.allocate(6);
buf.putShort(packet.packetType()); // 2바이트: 패킷 타입
buf.putInt(packet.targetId());     // 4바이트: 대상 ID
byte[] payload = buf.array();

// [전송 계층] TCP 소켓으로 전송 — OS가 세그먼트 분할·포트 관리
// 4계층(포트 번호)은 OS 스택이 처리, 애플리케이션은 write()만 호출
SocketChannel channel = ...;
channel.write(ByteBuffer.wrap(payload));

// [수신 측 응용 계층] 역캡슐화 후 메시지 복원
ByteBuffer recv = ByteBuffer.allocate(6);
channel.read(recv);
recv.flip();
short type = recv.getShort();
int targetId = recv.getInt();
// 이후 서버 로직: 사거리 검증, 쿨타임 확인, 데미지 계산
```

```text
송신                                          수신
[AttackPacket 구조체]                    [AttackPacket 구조체]  ← 응용
       ↓ 직렬화                                  ↑ 역직렬화
[바이트 배열 payload]                    [바이트 배열 payload]  ← 표현
       ↓ TCP 소켓 write()                         ↑ TCP read()
[TCP 세그먼트 (포트 붙음)]             [TCP 세그먼트]           ← 전송
       ↓ OS IP 스택                               ↑
[IP 패킷 (IP 주소 붙음)]               [IP 패킷]               ← 네트워크
       ↓ NIC 드라이버                             ↑
[Ethernet 프레임 (MAC 붙음)]          [Ethernet 프레임]        ← 데이터 링크
       ↓ 물리 신호 ─────────────────────────────↑             ← 물리
```

## 5. 비슷한 개념과 비교

### OSI 모델과 TCP/IP 모델

| 구분 | OSI 7계층 | TCP/IP 모델 |
|---|---|---|
| 목적 | 통신 기능을 설명하는 참조 모델 | 인터넷에서 실제 사용되는 프로토콜 체계 중심 모델 |
| 계층 수 | 7개 | 보통 4개로 설명 |
| 상위 계층 | 응용·표현·세션 | 응용 계층으로 통합 |
| 전송 계층 | 전송 | 전송 |
| 네트워크 계층 | 네트워크 | 인터넷 |
| 하위 계층 | 데이터 링크·물리 | 네트워크 접근 계층으로 통합 |

대략적인 대응 관계는 다음과 같다.

```text
OSI                         TCP/IP
7 응용 ┐
6 표현 ├------------------> 응용
5 세션 ┘
4 전송 -------------------> 전송
3 네트워크 ---------------> 인터넷
2 데이터 링크 ┐
1 물리       ┘------------> 네트워크 접근
```

OSI는 역할을 세밀하게 설명할 때 유용하고, TCP/IP 모델은 오늘날 인터넷 프로토콜의 실제 구성을 설명하기에 자연스럽다. 두 모델 중 하나만 옳은 것이 아니다. 면접에서는 OSI가 개념적 모델이라는 점과 실제 프로토콜의 경계가 정확히 일치하지 않을 수 있다는 점을 함께 말하는 것이 좋다.

## 6. 장점과 단점

### 장점

- 복잡한 통신 과정을 책임별로 나누어 학습하고 설계하기 쉽다.
- 계층 사이의 인터페이스를 기준으로 기술을 독립적으로 교체하기 쉽다.
- 장애가 발생한 계층을 기준으로 원인 범위를 단계적으로 좁힐 수 있다.
- 개발자, 네트워크 엔지니어, 운영자가 문제를 설명할 공통 언어를 제공한다.

### 단점

- 실제 인터넷 프로토콜은 계층 경계에 정확히 맞지 않는 경우가 있다.
- 모든 통신 과정을 일곱 단계에 억지로 끼워 맞추면 오히려 설명이 부정확해질 수 있다.
- 계층 분리는 이해를 돕지만 실제 처리 비용이나 구현 복잡성을 자동으로 줄여 주지는 않는다.

## 7. 게임 서버·백엔드 실무 예시

### 접속 장애를 계층별로 분석하기

게임 클라이언트가 서버에 접속하지 못한다면 다음 순서로 범위를 좁힐 수 있다.

```text
1계층: 케이블·무선 연결과 네트워크 인터페이스가 정상인가?
  ↓
2계층: 같은 네트워크 구간의 통신과 MAC 주소 해석이 정상인가?
  ↓
3계층: 서버 IP까지 경로가 있고 방화벽이 IP를 차단하지 않는가?
  ↓
4계층: 서버가 해당 TCP/UDP 포트에서 대기하며 연결이 성립하는가?
  ↓
7계층: 로그인 프로토콜, 인증 토큰, 메시지 형식이 올바른가?
```

예를 들어 서버 IP로는 연결되지만 로그인 요청에 오류 응답이 온다면 물리·링크·IP·전송 경로는 대체로 동작한다고 볼 수 있다. 조사 초점을 인증이나 메시지 버전 같은 응용 계층 문제로 옮길 수 있다. 반대로 TCP 연결 자체가 시간 초과된다면 애플리케이션 코드를 보기 전에 라우팅, 보안 그룹, 포트 리스닝 상태를 확인하는 편이 합리적이다.

### 패킷 크기와 계층의 상호작용

게임 서버가 큰 상태 스냅샷을 보내면 응용 계층 메시지는 전송 계층과 네트워크 계층에서 여러 단위로 나뉠 수 있다. TCP는 바이트 스트림이므로 한 번의 `Send`가 상대의 한 번의 `Receive`와 대응한다고 가정할 수 없다. 응용 계층에서 길이 필드 같은 메시지 경계를 별도로 정의해야 한다.

또한 하위 계층의 MTU(Maximum Transmission Unit)를 고려하지 않은 큰 UDP 데이터그램은 IP 단편화 위험을 높인다. 이 사례는 계층이 분리되어 있어도 상위 계층 설계자가 하위 계층의 중요한 제약을 알아야 한다는 점을 보여 준다.

## 8. 자주 하는 오해

### “OSI 7계층은 인터넷이 그대로 구현한 구조다”

OSI 7계층은 통신 기능을 나눠 이해하기 위한 참조 모델이다. 실제 인터넷은 TCP/IP 프로토콜 모음을 중심으로 발전했으며, 표현·세션 기능이 응용 프로그램에 포함되는 경우가 많다.

### “각 프로토콜은 반드시 한 계층에만 속한다”

실제 프로토콜과 장비는 여러 계층의 역할을 함께 수행할 수 있다. 계층 분류는 책임을 설명하는 도구이지 모든 구현의 절대적인 경계가 아니다.

### “응용 계층은 웹 브라우저 같은 애플리케이션 자체다”

응용 계층은 애플리케이션이 네트워크로 통신할 때 사용하는 서비스와 프로토콜을 뜻한다. 브라우저 전체나 게임 클라이언트 전체가 곧 7계층이라는 의미는 아니다.

### “TCP를 사용하면 응용 메시지 경계도 보존된다”

TCP는 순서 있는 바이트 스트림을 제공하지만 메시지 단위는 보존하지 않는다. 게임 패킷의 길이 또는 구분자는 응용 계층 프로토콜이 정의해야 한다.

### “2계층 MAC 주소로 인터넷 끝까지 전달한다”

MAC 주소는 기본적으로 현재 링크 구간의 전달에 사용된다. 라우터를 지날 때 링크 계층 프레임은 다음 구간에 맞게 다시 만들어지고, 종단 목적지를 나타내는 IP 주소는 라우팅에 사용된다.

### “7계층 문제면 애플리케이션 코드를 먼저 봐야 한다”

장애 계층 특정 없이 코드부터 보면 원인 찾는 시간이 늘어난다. TCP 연결 자체가 타임아웃된다면 응용 코드 전에 라우팅·보안 그룹·포트 리스닝을 확인하는 게 합리적이다. 계층 순서로 확인 범위를 좁힌 뒤 코드를 보는 것이 효율적이다.

### “세션 계층이 없으면 세션 관리가 불가능하다”

OSI 5계층 세션 기능은 현대 인터넷에서 별도 계층으로 구현되지 않는다. HTTP 쿠키, JWT, 게임 서버의 SessionManager처럼 응용 계층이 직접 세션을 관리한다. TCP/IP 모델에서 세션·표현 계층은 응용 계층에 통합된다.

## 9. 면접 질문

### Q1. OSI 7계층을 설명해 주세요.

OSI 7계층은 네트워크 통신 기능을 응용, 표현, 세션, 전송, 네트워크, 데이터 링크, 물리 계층으로 나눈 참조 모델이다. 각 계층은 정해진 책임을 수행하고 상위 계층에 서비스를 제공한다. 이를 통해 복잡성을 낮추고 프로토콜 설계와 장애 분석을 체계화할 수 있다.

### Q2. 캡슐화와 역캡슐화란 무엇인가요?

캡슐화는 송신 데이터가 상위 계층에서 하위 계층으로 내려가면서 TCP, IP, 프레임 등의 제어 정보가 붙는 과정이다. 역캡슐화는 수신 측에서 각 계층이 해당 정보를 확인하고 제거해 원래 응용 데이터를 복원하는 과정이다.

### Q3. 전송 계층과 네트워크 계층의 차이는 무엇인가요?

네트워크 계층은 IP 주소와 라우팅을 이용해 목적지 호스트까지 패킷이 갈 경로를 다룬다. 전송 계층은 포트 번호를 사용해 호스트 안의 프로세스를 구분하고, TCP의 경우 신뢰성·순서·흐름 제어를 제공한다.

### Q4. 데이터 링크 계층과 네트워크 계층의 주소는 어떻게 다른가요?

데이터 링크 계층의 MAC 주소는 주로 현재 링크 안에서 프레임을 전달하는 데 사용된다. 네트워크 계층의 IP 주소는 여러 네트워크를 지나 최종 호스트를 찾아가는 데 사용된다.

### Q5. OSI 모델과 TCP/IP 모델의 차이는 무엇인가요?

OSI는 통신 기능을 일곱 계층으로 세분화한 개념적 참조 모델이다. TCP/IP 모델은 실제 인터넷 프로토콜 구성을 중심으로 보통 응용, 전송, 인터넷, 네트워크 접근의 네 계층으로 설명한다.

### Q6. 게임 서버에서 OSI 계층 지식이 실무에 어떻게 활용되나요?
클라이언트 접속 장애 시 물리 연결 → IP 경로 → TCP 포트 → 응용 프로토콜 순서로 범위를 좁힙니다. TCP가 연결되지만 로그인이 실패한다면 하위 계층이 정상임을 알고 인증·메시지 형식 같은 7계층 문제에 집중합니다. 또한 큰 상태 스냅샷 전송 시 TCP 바이트 스트림 특성(메시지 경계 없음)을 알아야 응용 계층에서 길이 필드를 별도로 정의해 패킷 프레이밍을 구현할 수 있습니다.

## 11. 30초 모범답변

> OSI 7계층은 네트워크 통신 기능을 응용부터 물리 계층까지 역할별로 나눈 참조 모델입니다. 송신 측에서는 데이터에 전송, IP, 링크 계층 정보가 차례로 붙는 캡슐화가 일어나고, 수신 측에서는 반대로 제거됩니다. 실제 인터넷은 주로 TCP/IP 모델로 구현되지만, OSI 모델은 통신 구조를 이해하고 IP 문제인지 포트 문제인지 응용 프로토콜 문제인지 장애 범위를 좁히는 데 유용합니다.

## 12. 1~2분 확장답변

> OSI 7계층은 복잡한 네트워크 통신을 역할별로 나눈 개념적 참조 모델입니다. 위에서부터 응용, 표현, 세션, 전송, 네트워크, 데이터 링크, 물리 계층으로 구성됩니다. 응용 계층은 HTTP나 게임 메시지 같은 네트워크 서비스를 제공하고, 표현 계층은 직렬화·인코딩·암호화를, 세션 계층은 대화의 설정과 유지를 담당합니다. 전송 계층은 TCP나 UDP를 사용해 포트 기반의 프로세스 간 통신을 제공하고, 네트워크 계층은 IP 주소와 라우팅으로 목적지 호스트까지 경로를 선택합니다. 데이터 링크 계층은 같은 링크에서 MAC 주소 기반으로 프레임을 전달하며, 물리 계층은 이를 실제 비트 신호로 보냅니다. 송신할 때는 계층별 헤더가 붙는 캡슐화가, 수신할 때는 이를 제거하는 역캡슐화가 일어납니다. 실제 인터넷에서는 표현과 세션 계층을 응용 계층에 합친 TCP/IP 모델을 주로 사용합니다. 그래도 OSI 모델은 게임 서버 접속 장애가 네트워크 경로인지, TCP 포트인지, 로그인 프로토콜인지 단계적으로 구분하는 데 유용합니다.

## 13. 핵심 요약

- OSI 7계층은 네트워크 통신의 책임을 일곱 단계로 나눈 개념적 참조 모델이다.
- 송신 측은 계층별 제어 정보를 붙여 캡슐화하고, 수신 측은 이를 제거해 역캡슐화한다.
- 7계층(응용)은 HTTP·게임 프로토콜, 4계층(전송)은 TCP/UDP·포트, 3계층(네트워크)은 IP·라우팅, 2계층(데이터 링크)은 MAC·프레임, 1계층(물리)은 비트 신호를 담당한다.
- MAC 주소는 링크 구간 전달에만 사용되고 라우터를 지나면 새 프레임이 만들어진다. IP 주소가 종단 간 경로를 나타낸다.
- TCP는 순서 있는 바이트 스트림을 제공하지만 메시지 경계를 보장하지 않는다. 게임 패킷 경계는 응용 계층에서 길이 필드로 정의해야 한다.
- 실제 인터넷은 보통 4계층 TCP/IP 모델로 설명하지만, OSI 모델은 역할 이해와 장애 분석에 유용하다.
- 장애 분석 순서: 물리 연결 → IP 경로·방화벽 → TCP 포트 리스닝 → 응용 프로토콜·인증.
- 계층 경계는 설명을 위한 기준이며 TLS처럼 실제 프로토콜이 특정 계층에 정확히 맞지 않는 경우도 있다.

## 한 줄 정리

> OSI 7계층은 네트워크 통신을 역할별로 분리해 데이터 전달 과정을 이해하고 장애 원인을 체계적으로 찾게 해 주는 참조 모델이다.
