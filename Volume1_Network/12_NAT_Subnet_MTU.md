# 12. NAT, Subnet, MTU

> 게임 서버·백엔드 개발자를 위한 CS 면접 교재

## 학습 목표

- NAT의 주소·포트 변환과 연결 제약을 설명할 수 있다.
- 서브넷이 주소와 브로드캐스트 범위를 나누는 방식을 설명할 수 있다.
- MTU, IP 단편화, Path MTU 문제를 게임 패킷 설계에 적용할 수 있다.

## 1. 개요

NAT(Network Address Translation)는 패킷이 경계를 지날 때 IP 주소나 포트를 변환한다. 서브넷(Subnet)은 하나의 IP 네트워크를 더 작은 네트워크로 나눈다. MTU(Maximum Transmission Unit)는 한 링크 계층 프레임이 담을 수 있는 네트워크 계층 패킷의 최대 크기다.

세 개념은 각각 주소 부족과 경계 연결, 네트워크 분할, 패킷 크기 제약을 다룬다.

## 2. 왜 필요한가

IPv4 주소는 제한적이므로 여러 사설 호스트가 공인 주소를 공유할 필요가 생겼다. 네트워크를 역할별로 나누면 브로드캐스트와 접근 정책을 관리하기 쉽다. 링크마다 한 번에 운반할 수 있는 크기가 다르므로 큰 패킷을 어떻게 처리할지도 결정해야 한다.

## 3. 핵심 동작 원리

### NAT와 PAT

가정용 공유기나 클라우드 NAT Gateway는 내부 출발지 주소와 포트를 외부 공인 주소와 다른 포트로 변환하고 매핑을 저장한다. 포트까지 변환하는 방식을 PAT 또는 NAPT라고도 한다.

```text
10.0.0.10:51000 ─┐
                  ├─ NAT ─ 198.51.100.7:40001 ─> Server:443
10.0.0.20:51000 ─┘       198.51.100.7:40002
```

응답이 돌아오면 NAT 장비는 매핑을 보고 원래 내부 호스트로 전달한다. 외부에서 내부로 먼저 연결하려면 기존 매핑, 포트 포워딩, 중계 서버, NAT 통과 기법 등이 필요하다. NAT 매핑에는 유휴 시간 제한이 있어 장시간 조용한 UDP 세션은 사라질 수 있다.

NAT는 내부 주소를 직접 노출하지 않지만 방화벽과 같은 보안 기능으로 간주해서는 안 된다. 접근 통제 정책은 별도로 필요하다.

#### NAT 매핑과 포트 고갈

NAT 장비는 보통 프로토콜과 내부·외부 주소 및 포트의 조합을 기준으로 흐름을 구분한다. 정확한 매핑 방식과 외부에서 허용되는 응답 범위는 장비마다 다를 수 있다. 그래서 한 NAT에서는 성공한 P2P 연결 방식이 다른 통신사망에서는 실패할 수 있다. STUN으로 외부 매핑을 관찰하고 직접 연결을 시도하되, 실패하면 TURN 같은 중계로 전환하는 이유다.

하나의 공인 IP가 만들 수 있는 동시 변환 포트 수는 유한하다. 많은 백엔드 인스턴스가 같은 목적지로 짧은 연결을 반복하면 포트 고갈이 발생해 새 연결만 실패할 수 있다. 공인 IP 추가, 목적지 분산, 연결 풀과 Keep-Alive, 유휴 매핑 시간 조정으로 완화한다. 단순히 서버 CPU와 메모리만 확인해서는 이 병목을 찾기 어렵다.

### 서브넷과 CIDR

`10.0.0.0/24`에서 앞 24비트는 네트워크 접두사이고 나머지는 호스트 부분이다. 더 긴 접두사로 나누면 작은 서브넷을 만들 수 있다.

```text
10.0.0.0/24
  ├─ 10.0.0.0/25    (0~127)
  └─ 10.0.0.128/25  (128~255)
```

서브넷이 다르면 일반적으로 라우터를 통해 통신한다. 이를 이용해 공개 로드 밸런서, 애플리케이션, DB를 별도 네트워크에 두고 라우팅과 방화벽 정책을 다르게 적용한다. 서브넷 분리 자체가 접근 차단은 아니며 정책이 필요하다.

CIDR 포함 관계는 비트 접두사로 판단한다. 예를 들어 `10.0.0.64/26`은 주소 범위가 `10.0.0.64`부터 `10.0.0.127`까지다. 전통적인 IPv4 서브넷에서는 첫 주소를 네트워크 주소, 마지막 주소를 브로드캐스트 주소로 예약한다. 다만 클라우드 플랫폼은 추가 주소를 자체 기능에 예약할 수 있으므로 실제 사용 가능 개수는 플랫폼 규칙도 확인한다.

서브넷이 겹치면 VPN이나 네트워크 피어링에서 어느 경로를 선택해야 할지 모호해진다. 초기에는 넉넉한 사설 대역을 임의로 쓰기보다 향후 연결할 조직·리전의 주소 계획까지 고려한다.

### MTU와 단편화

Ethernet의 흔한 MTU는 1500바이트지만 터널과 경로에 따라 실제 사용 가능한 크기가 작아질 수 있다. IPv4 라우터는 조건에 따라 패킷을 단편화할 수 있고, DF 비트가 설정되면 단편화하지 않고 ICMP 오류를 돌려준다. IPv6 라우터는 중간에서 단편화하지 않는다.

```text
Application data
   + UDP header
   + IP header
   <= Path MTU를 고려한 크기
```

UDP 데이터그램이 단편화되면 한 조각만 유실되어도 전체 데이터그램을 재조립할 수 없다. 일부 방화벽이 단편을 다르게 처리해 도달률이 낮아질 수도 있다.

Path MTU Discovery는 경로에서 허용되는 최대 패킷 크기를 찾는다. 필요한 ICMP 메시지가 차단되면 큰 패킷만 사라지는 PMTUD Black Hole이 발생할 수 있다. 작은 요청은 성공하지만 큰 응답이나 특정 패킷만 멈추는 증상으로 나타날 수 있다.

TCP는 일반적으로 MSS(Maximum Segment Size)를 협상해 IP와 TCP 헤더를 제외한 세그먼트 데이터 크기를 제한한다. 터널이나 VPN 환경에서는 MSS 조정이 필요할 수 있다.

애플리케이션이 `send()` 한 번에 4KB를 전달했다고 해서 네트워크에 4KB짜리 TCP 패킷 하나가 나가는 것은 아니다. TCP는 MSS에 맞춰 세그먼트로 나누고 수신 측에서는 다시 바이트 스트림으로 제공한다. 반면 UDP의 한 번 송신은 하나의 데이터그램 경계를 만들므로 큰 데이터그램 자체가 IP 단편화 위험을 가진다. 이 차이는 TCP의 메시지 경계 처리와 UDP 패킷 크기 설계에 직접 연결된다.

## 4. 쉬운 예시

집의 두 게임 클라이언트는 각각 사설 IP를 갖지만 같은 공인 IP로 서버에 접속한다. NAT는 서로 다른 외부 포트 매핑으로 두 세션을 구분한다. 따라서 게임 서버가 공인 IP만 보고 사용자를 고유하게 식별하면 두 사용자를 같은 사람으로 오판할 수 있다.

게임의 큰 월드 스냅샷을 하나의 UDP 데이터그램으로 보내면 경로 MTU를 넘어 여러 IP 조각이 될 수 있다. 서버가 응용 계층에서 작은 청크로 나누면 손실 시 필요한 조각만 다시 보내거나 최신 스냅샷으로 대체할 수 있다.

## 5. 비슷한 개념과 비교

| 개념 | 해결하는 문제 | 핵심 주의점 |
|---|---|---|
| NAT | 주소·포트 변환과 공인 IPv4 공유 | 종단 직접 연결, 매핑 만료 |
| Subnet | 주소 공간과 네트워크 범위 분할 | 라우팅·보안 정책 별도 필요 |
| MTU | 한 링크에서 운반할 패킷 크기 | 단편화와 경로별 차이 |

MTU는 IP 패킷 전체의 링크 한도이고 MSS는 TCP 세그먼트의 데이터 부분 크기다. 같은 값이 아니다.

## 6. 장점과 단점

NAT는 IPv4 공인 주소를 절약하고 내부 주소 설계를 독립시킨다. 반면 연결 상태를 장비가 관리하고 P2P와 추적을 복잡하게 한다. 서브넷은 장애와 정책 범위를 분리하지만 잘못된 CIDR과 라우팅은 통신 단절을 만든다. 큰 MTU는 헤더 오버헤드를 줄일 수 있지만 모든 경로가 지원하지 않으며 단편화 손실 위험이 있다.

## 7. 게임 서버·백엔드 실무 예시

UDP 게임 서버는 NAT 매핑 유지를 위해 하트비트를 사용하고, 연결 재개 시 새 주소·포트를 인증된 세션에 안전하게 연결한다. 패킷의 출발지 주소만 믿으면 스푸핑이나 세션 탈취 위험이 있다.

클라우드에서는 public, application, database 서브넷을 나누고 최소 경로만 허용한다. NAT Gateway 장애나 포트 고갈도 관찰한다. 많은 내부 서버가 동일 외부 서비스에 연결하면 하나의 공인 주소에서 사용할 변환 포트가 부족해질 수 있다.

MTU 문제는 “로그인은 되지만 큰 캐릭터 데이터에서 멈춤”처럼 보일 수 있다. 패킷 캡처, 크기별 요청 시험, ICMP 차단 여부, VPN·터널 오버헤드를 확인한다.

## 8. 자주 하는 오해

- “NAT는 방화벽이다”: 변환과 접근 제어는 별개다.
- “사설 IP 하나가 사용자 한 명이다”: NAT와 DHCP 때문에 아니다.
- “서브넷을 나누면 자동 차단된다”: 라우팅과 방화벽 정책이 필요하다.
- “MTU는 인터넷 전체에서 1500이다”: 경로와 터널마다 다를 수 있다.
- “TCP는 MTU를 신경 쓰지 않아도 된다”: PMTU와 MSS가 성능·도달성에 영향을 준다.

### 최종 실무 판단 기준

- **요구 확인**: NAT는 주소·포트를 변환하고 상태 매핑을 유지한다. 이 내용을 적용하기 전에 데이터 규모, 호출 빈도와 허용 지연을 수치로 확인한다. 같은 기술도 요청량과 정확성 요구가 달라지면 적합한 선택이 달라질 수 있다.
- **정확성 경계**: 서브넷은 CIDR로 네트워크와 정책 범위를 나눈다. 정상 흐름만 설명하지 않고 중복, 역순, 동시 실행과 부분 실패에서 어떤 불변식을 지켜야 하는지 함께 명시한다.
- **비용 비교**: MTU는 링크가 운반할 IP 패킷 최대 크기다. 평균 복잡도나 처리량 하나만 보지 않고 Memory, CPU, I/O, Lock 대기와 구현 복잡도까지 비교한다.
- **장애 대응**: NAT, Subnet, MTU 관련 구성 요소가 느려지거나 중단됐을 때 Timeout, Retry 상한, Backpressure와 복구 순서를 정한다. Retry가 중복 부작용이나 연쇄 부하를 만들지 검증한다.
- **운영 검증**: NAT, Subnet, MTU에서는 기능 Test와 함께 경계값, Peak 부하와 장애 주입 Test를 수행한다. 처리 시간 p95·p99, 오류율, Queue와 Resource 사용량을 관찰하고 변경 전후 결과를 비교한다.

NAT, Subnet, MTU 답변에서는 이 기준으로 답하면 개념 정의에 그치지 않고 선택 조건, Trade-off와 실무 검증 방법까지 논리적으로 연결할 수 있다.

## 9. 면접 질문

### Q1. NAT는 어떻게 동작하나요?

경계 장비가 내부 IP와 포트를 공인 IP와 외부 포트로 변환하고 매핑을 저장한다. 응답은 이 매핑을 이용해 원래 내부 호스트로 전달한다.

### Q2. 서브넷을 나누는 이유는 무엇인가요?

주소를 효율적으로 할당하고 브로드캐스트, 장애, 라우팅과 보안 정책 범위를 분리하기 위해서다.

### Q3. MTU를 넘는 UDP 데이터그램은 어떤 문제가 있나요?

IP 단편화될 수 있고 조각 하나만 유실되어도 전체 데이터그램을 사용할 수 없다. 방화벽과 터널 환경에서 도달성도 나빠질 수 있어 응용 계층에서 작게 나누는 편이 좋다.

### Q4. MTU와 MSS의 차이는 무엇인가요?

MTU는 링크가 운반할 IP 패킷 최대 크기이고, MSS는 TCP 헤더와 IP 헤더를 제외한 TCP 데이터 최대 크기다.

### Q5. NAT Gateway의 포트 고갈은 왜 발생하나요?

공인 IP와 목적지 조합에서 사용할 수 있는 변환 포트가 유한하기 때문이다. 짧은 외부 연결을 대량 생성하면 매핑이 남아 새 연결에 배정할 포트가 부족해질 수 있다. 연결 재사용, 공인 IP 추가, 목적지 분산과 관련 지표 관찰이 필요하다.

## 11. 30초 모범답변

> NAT는 경계에서 IP와 포트를 변환해 여러 사설 호스트가 공인 IPv4를 공유하게 합니다. 서브넷은 CIDR 접두사로 네트워크를 나눠 주소와 정책 범위를 관리합니다. MTU는 링크가 운반할 IP 패킷의 최대 크기이며, 게임의 큰 UDP 데이터그램이 이를 넘으면 단편화되어 조각 하나의 손실로 전체가 폐기될 수 있으므로 패킷 크기를 보수적으로 설계해야 합니다.

## 12. 1~2분 확장답변

> NAT 장비는 내부 주소와 포트를 공인 주소와 포트로 바꾸고 상태 매핑으로 응답을 돌려줍니다. IPv4 주소 절약에는 유용하지만 외부의 최초 연결과 P2P, 매핑 만료를 복잡하게 만듭니다. 서브넷은 주소의 네트워크 접두사를 기준으로 더 작은 네트워크를 만들며 역할별 라우팅과 보안 범위를 나누는 데 사용합니다. MTU는 링크가 한 프레임에 담을 수 있는 IP 패킷 크기입니다. 경로 MTU보다 큰 UDP 데이터그램은 단편화 위험이 있고 한 조각 손실로 전체가 사라집니다. 게임 서버에서는 NAT 하트비트, 인증된 주소 변경, 작은 UDP 패킷, 터널 환경의 MTU를 함께 고려해야 합니다.

## 13. 핵심 요약

- NAT는 주소·포트를 변환하고 상태 매핑을 유지한다.
- 서브넷은 CIDR로 네트워크와 정책 범위를 나눈다.
- MTU는 링크가 운반할 IP 패킷 최대 크기다.
- 큰 UDP 데이터그램의 단편화는 손실 영향을 키운다.
- NAT와 서브넷은 보안 정책 자체가 아니다.
- NAT의 상태 테이블과 변환 포트도 유한한 운영 자원이다.

## 한 줄 정리

> NAT는 주소 경계를 넘게 하고, 서브넷은 네트워크를 나누며, MTU는 한 번에 보낼 수 있는 패킷 크기를 제한한다.
